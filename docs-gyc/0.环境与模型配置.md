## 背景：Cosmos-Predict2.5 模型体系

Cosmos-Predict2.5 是一个**视频生成模型**，所有变体都在同一个 HuggingFace 仓库 `nvidia/Cosmos-Predict2.5-2B` 中，共享同一个 DiT 2B 架构，针对不同场景做了不同方向的后训练：

```
nvidia/Cosmos-Predict2.5-2B/
├── tokenizer.pth                        485MB  共用的视频 tokenizer
│
├── base/                                ← 通用视频生成
│   ├── pre-trained/   ............  3.9G  基础预训练（所有模型的起点）
│   ├── post-trained/  ............  3.9G  基础后训练（Image2World 推理用）
│   └── distilled/     ............  3.9G  蒸馏模型（4步快速推理）
│
├── auto/                                ← 自动驾驶场景
│   └── multiview/     ............  3.9G  多视角后训练
│
└── robot/                               ← ★ 机器人场景（我们关注的）
    ├── action-cond/   ............  4.0G  Action-Conditioned 世界模型（单臂 7 维，训练起点）
    ├── multiview-agibot/           4.0G  AgiBot 多视角
    └── policy/
        ├── libero/                 3.9G  策略模型 (LIBERO)
        └── robocasa/               3.9G  策略模型 (RoboCasa)
```

模型统一缓存在 `/mnt/gyc_ckp/`，所有服务器通过共享挂载访问：

```
/mnt/gyc_ckp/
├── hf_cache/          ← HF_HOME，推理时自动从这里加载（含 Guardrail、tokenizer 等）
└── models/
    ├── Cosmos-Predict2.5-2B/    ← 平铺的模型权重文件（训练 load_path 直接指向这里）
    │   ├── tokenizer.pth
    │   ├── base/post-trained/
    │   └── robot/action-cond/   ← 后训练起点
    └── Cosmos-Reason1-7B/       ← 文本编码器
```

## 1. 系统要求确认

```bash
nvidia-smi                          # GPU 架构（需要 Ampere 或更新）
nvidia-smi | grep "Driver Version"  # 驱动版本（官方要求 ≥570，实测 535 可用）
nvcc --version                      # CUDA 版本（官方要求 12.8，实测 12.2 可用）
lsb_release -a                      # 操作系统（需要 Ubuntu ≥22.04）
ldd --version                       # glibc 版本（需要 ≥2.35）
```

实测环境：

| 项目 | 要求 | 实际 | 状态 |
|------|------|------|------|
| GPU 架构 | Ampere 或更新 | NVIDIA A800-SXM4-80GB | ✅ |
| NVIDIA 驱动 | ≥570.124.06 | 535.161.08 | ⚠️ 低于要求，但可用 |
| CUDA 版本 | 12.8.1 | 12.2 | ⚠️ 低于要求，但可用 |
| 操作系统 | Ubuntu ≥22.04 | Ubuntu 22.04.3 LTS | ✅ |
| glibc | ≥2.35 | 2.35 | ✅ |

> uv Python 位于 `/mnt/gyc/uv-python/cpython-3.10.18-linux-x86_64-gnu/`，`.venv` 软链接指向此处，所有服务器共享。

## 6. 创建 Conda 环境并安装依赖

```bash
# 创建 conda 环境
conda create -n cosmos-predict2.5 python=3.10 -y
conda activate cosmos-predict2.5

# 挂代理（如需要）
export http_proxy=http://192.168.32.28:18000
export https_proxy=http://192.168.32.28:18000

# 用 uv 安装所有依赖到 .venv（指定共享存储的 Python）
UV_PYTHON=/mnt/gyc/uv-python/cpython-3.10.18-linux-x86_64-gnu/bin/python3.10 \
  uv sync --extra=cu128 --active --inexact
```

> 磁盘空间不足时先执行 `uv cache clean` 再重试。

已安装关键包：torch 2.7.0+cu128、flash-attn 2.7.3+cu128、transformer-engine 2.2+cu128。

## 8. 新服务器配置（仅需一次）

共享挂载已包含 `.venv`、conda 环境和模型，新服务器只需：

### 8.1 libcudart.so 软链接

部分服务器只有带版本号的 `.so`，需要手动建软链接：

```bash
# 检查是否已有
ls /usr/local/cuda-12.2/lib64/libcudart.so

# 没有则创建
ln -s /usr/local/cuda-12.2/lib64/libcudart.so.12 /usr/local/cuda-12.2/lib64/libcudart.so
```

### 8.2 修复 NVML/RM 版本不匹配

训练启动时若报 `NVMLError_LibRmVersionMismatch`，原因是 `libnvidia-ml.so.1` 软链接指向的版本和内核驱动版本不一致。

实测环境：

| 项目 | 值 |
|------|----|
| 内核驱动版本（`/proc/driver/nvidia/version`） | **535.161.08** |
| `libnvidia-ml.so.1` 原始指向 | `libnvidia-ml.so.535.183.06`（文件不存在） |
| 修复后指向 | `libnvidia-ml.so.535.161.08` |

**检查：**

```bash
# 内核驱动版本
cat /proc/driver/nvidia/version

# libnvidia-ml.so.1 当前指向什么
ls -la /usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1
```

如果两者版本号不一致，则修复：

```bash
ln -sf /usr/lib/x86_64-linux-gnu/libnvidia-ml.so.535.161.08 /usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1
```

### 8.3 验证环境

```bash
conda activate cosmos-predict2.5
source /mnt/gyc/cosmos-predict2.5/.venv/bin/activate
python -c "import torch; print(torch.__version__)"
```
