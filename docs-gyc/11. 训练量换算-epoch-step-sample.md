# 11. 训练量换算 — epoch / step / sample 三个单位

> 本文档把 RoboTwin 14D 后训练和 DMD2 蒸馏的训练量在三个单位之间做换算，并给出公式推导。目的是回答"我们到底跑了多少个 epoch、每个 epoch 多少 step、整个训练过了多少样本"这种量级问题。

## 一、三个单位怎么定义

训练量有三种单位，别混。

| 单位 | 含义 | 和 batch_size 的关系 |
|---|---|---|
| **sample** | `Dataset_3D.__getitem__` 返回的一条数据 = 一个 `(episode, start_frame)` 对应的 13 帧片段 | 一个 step 吃 `batch_size` 个 sample |
| **step** (= iter) | 1 次 forward/backward，吃一个 batch | `step = sample / batch_size` |
| **epoch** | DataLoader 把整个 dataset 遍历一次 | `epoch = step / steps_per_epoch` |

训练 log 里看到的 `iter_000150000` 是 **step 数**，不是 sample 数、也不是 epoch 数。

---

## 二、dataset_size 怎么算（按样本）

### 2.1 一个样本是什么

`Dataset_3D` 的 `_load_and_process_ann_file` 逻辑：对每个 episode，从 `frame_i = 0` 开始，尝试取 13 帧（隔 `fps_downsample_ratio` 取一帧）。能凑齐 13 帧的起点就算一个合法样本。

所以 **一个样本 = 一个 `(episode_id, start_frame)` 对**，对应 13 帧连续片段（抽帧时跨度拉长）。

### 2.2 每个 episode 能切多少样本

一个样本的物理跨度 = `12 × fps_downsample_ratio` 帧（从 start 到 start+12×fps_ds）。

合法起点 `start` 必须满足 `start + 12×fps_ds ≤ n - 1`，即 `start ≤ n - 1 - 12×fps_ds`。

**每个 episode 的合法起点数 = `max(0, n_frames - 12 × fps_downsample_ratio)`**

### 2.3 全训练集求和

```
dataset_size = Σ max(0, n_i - 12 × fps_downsample_ratio)
             ^
             180 个 episode 分别算，再加起来
```

### 2.4 RoboTwin 的实际数字

180 个训练 episode 的帧数统计：

| 项 | 值 |
|---|---:|
| 最短 episode | 150 帧 |
| 最长 episode | 281 帧 |
| 平均每 episode | 198.5 帧 |
| **Σ n_i**（180 个 episode 原始帧数总和） | **35,722** |

**实际跑的是 `fps_downsample_ratio=10`**（详见 [`7.帧数与分辨率定义-官方vsRoboTwin.md`](7.帧数与分辨率定义-官方vsRoboTwin.md)），代入：

```
dataset_size = Σ (n_i - 120)
             = 35,722 - 180 × 120
             = 35,722 - 21,600
             = 14,122
```

**这个 14,122 就是 `Dataset_3D.__len__()` 的返回值**，即 **1 帧条件 + 12 帧动作切出来的全部 chunk 数量**。

## 三、从样本换到 step

```
steps_per_epoch = dataset_size_in_samples / global_batch_size
```

其中 `global_batch_size = per_gpu_batch × num_gpus`。

- **训练阶段**：per_gpu=2，GPU=8 → `global_batch = 16`
- **蒸馏阶段**：per_gpu=1，GPU=8 → `global_batch = 8`

## 四、epoch 公式

两种等价写法：

```
# 按样本口径
epochs = (max_iter × global_batch_size) / dataset_size_in_samples

# 按 step 口径（steps_per_epoch = dataset_size_in_samples / batch_size）
epochs = max_iter / steps_per_epoch
```

分子分母都约一个 `batch_size`，结果一致。

## 五、两阶段的实际数字

### 5.1 后训练（RoboTwin 14D）

```
dataset_size_in_samples = 14,122
global_batch_size = 16
steps_per_epoch = 14,122 / 16 ≈ 883

max_iter = 150,000

epochs = 150,000 × 16 / 14,122
       = 2,400,000 / 14,122
       ≈ 170 epochs
```

### 5.2 蒸馏（DMD2）

```
dataset_size_in_samples = 14,122   （同一训练集）
global_batch_size = 8
steps_per_epoch = 14,122 / 8 ≈ 1,766

max_iter = 30,000

epochs = 30,000 × 8 / 14,122
       = 240,000 / 14,122
       ≈ 17 epochs
```

### 5.3 汇总

| 阶段 | max_iter | global_batch | steps/epoch | **epochs** |
|---|---:|---:|---:|---:|
| **后训练** | 150,000 | 16 | 883 | **≈ 170** |
| **蒸馏** | 30,000 | 8 | 1,766 | **≈ 17** |

**训练 epoch 是蒸馏的 10×**。蒸馏需要的 epoch 少是因为 student 从 teacher 初始化，只需微调，不用学"物理分布"。

## 六、抽帧 vs 不抽帧对比

如果不抽帧（`fps_ds=1`）：

```
dataset_size = Σ (n_i - 12)
             = 35,722 - 180 × 12
             = 33,562 样本
```

| 配置 | dataset_size（样本） | steps/epoch (train) | steps/epoch (distill) | Training epochs | Distill epochs |
|---|---:|---:|---:|---:|---:|
| **抽帧 fps_ds=10（实跑）** | **14,122** | 883 | 1,766 | **170** | **17** |
| 不抽帧 fps_ds=1 | 33,562 | 2,098 | 4,195 | 71.5 | 7.2 |

> ⚠️ "不抽帧"物理上不可行：RoboTwin 30 FPS 下 13 帧只覆盖 0.43 秒，机器人动作跨度太小，学不到有效的 action-video 对应关系。选 `fps_ds=10` 把有效采样率降到 3 fps，使 13 帧覆盖约 4.3 秒，时间跨度和 Bridge 对齐。

---

## 七、实际耗时与 epoch 对应

| 阶段 | epochs | 总耗时 | 每 epoch | 每 iter |
|---|---:|---:|---:|---:|
| **后训练**（150k iter）| 170 | 54.5 h（2.3 天）| ≈ 19 min | ≈ 1.31 s |
| **蒸馏**（30k iter）| 17 | 13.8 h | ≈ 49 min | ≈ 1.66 s |

**观察**：

- 蒸馏单 epoch 耗时 ~2.5× 训练：因为每 iter 要算 student + teacher + fake_score 三张网络 + 两套 Adam state（见 [`10. 基于RoboTwin的Action-Conditioned蒸馏.md`](10.%20基于RoboTwin的Action-Conditioned蒸馏.md) §7.3）
- 蒸馏 epoch 数只有训练的 10%，总时长反而缩到训练的 25%
- 后训练平均 iter 速度 1.31 s 和 log 里观察到的"前半程 1.27 s / 后半程 2.10 s"对得上

---

## 八、一句话总结

- **后训练**：14,122 样本 × 170 epochs = 2.4M 样本过数据，170 epochs = 54.5 小时
- **蒸馏**：14,122 样本 × 17 epochs = 240K 样本过数据，17 epochs = 13.8 小时
- 两阶段数据集完全相同，差别在 `max_iter` + `global_batch_size`
