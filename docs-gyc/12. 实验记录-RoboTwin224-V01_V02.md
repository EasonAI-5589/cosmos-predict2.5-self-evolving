## 一、实验目标

**V0.1 (16 帧)** 和 **V0.2 (32 帧)** 的主要差异是单个 chunk 生成多少帧。两组其他参数完全一致，目的：

1. **对比 chunk size 对生成质量 / 收敛速度 / 训练成本的影响**：16 vs 32 哪个性价比高
2. **找最小收敛 epoch**：跑 100k iter 但 checkpoint 每 2k 保留一个，后期从中挑最早可用的 ckpt，加速后续迭代周期
3. **切到 224×224 方形分辨率**：对齐 Cosmos Policy 系列（`resolution=224`），为后续加 value head 做准备

**不含 value head**——value 这条路要明天重做 RoboTwin 数据（加 rollout/reward），本次先跑纯视频生成版。

## 三、训练量预算（理论）

复用 [`11. 训练量换算-epoch-step-sample.md`](11.%20训练量换算-epoch-step-sample.md) 的公式：

```
dataset_size = Σ max(0, n_i − num_action_per_chunk × fps_downsample_ratio)
             = 35,722 − 180 × (chunk × fps_ds)
```

### V0.1（chunk=16, fps_ds=1）

```
dataset_size = 35,722 − 180 × 16 = 32,842 samples
steps_per_epoch = 32,842 / 16 ≈ 2,053 steps
epochs = 100,000 × 16 / 32,842 ≈ 48.7 epochs
```

### V0.2（chunk=32, fps_ds=1）

```
dataset_size = 35,722 − 180 × 32 = 29,962 samples
steps_per_epoch = 29,962 / 16 ≈ 1,873 steps
epochs = 100,000 × 16 / 29,962 ≈ 53.4 epochs
```

### 训练时长估算

当前 AC 14D 训练实测 ~1.3 s/iter（见 doc 8）。V0.1 和 V0.2 因为 chunk 变长会变慢：

| 实验 | iter 估速 | 100k 总时长（单机 8 卡）|
|---|---|---|
| V0.1 | ~1.5 s/iter（+15%，chunk 16 vs 12）| ≈ **42 小时** |
| V0.2 | ~2.5 s/iter（+90%，chunk 32 vs 12，激活近 3×）| ≈ **70 小时** |

**两组同步跑 → 约 2-3 天出结果**。

### 对比 150k 参考基线

| 版本 | max_iter | chunk | fps_ds | dataset | steps/epoch | **epochs** |
|---|---:|---:|---:|---:|---:|---:|
| RoboTwin 14D (已完成) | 150,000 | 12 | 10 | 14,122 | 883 | **170** |
| **V0.1** | **100,000** | **16** | **1** | **32,842** | **2,053** | **≈ 49** |
| **V0.2** | **100,000** | **32** | **1** | **29,962** | **1,873** | **≈ 53** |

V0.1 / V0.2 的 **epoch 数只有基线的 1/3**，因为不抽帧带来 dataset 大 2.3×。如果后期发现 49-53 epoch 不够收敛，再增加 max_iter。

## 五、配置继承关系

```
AC_REASON_EMBEDDINGS_RECTIFIED_FLOW_2B                  ← 父实验（单臂 7D）
  ↓ defaults
AC_ROBOTWIN_14D_RECTIFIED_FLOW_2B                       ← RoboTwin 14D（action_dim=14, load 双臂 teacher）
  ↓ defaults
robotwin_14d_8gpu（= AC_ROBOTWIN_14D_RECTIFIED_FLOW_2B_8GPU） ← 8 卡派生
  ↓ CLI override
V0.1 / V0.2                                             ← 本次两组
```

**不新增 Python config**，两组完全靠 CLI override 实现。好处是：
- 不改代码
- 版本历史只有 git 里两个新 shell 脚本
- 想再起第三组（比如 chunk=24）直接抄脚本改一下就行
