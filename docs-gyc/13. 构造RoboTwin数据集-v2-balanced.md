## 一、为什么要重做

### 1.1 v1 的切分 bug

`scripts/convert_robotwin_to_cosmos.py` 第 125、128–135 行的逻辑是：

```python
all_episodes = []     # pcp 100 + pob 100 = 200，按 prefix 顺序累加
val_start = int(total * (1 - VAL_RATIO))   # 200 × 0.9 = 180
for i, ep in enumerate(all_episodes):
    split = "train" if i < val_start else "val"
```

因为 `TASKS` 字典 pcp 在前，前 100 全是 pcp，所以：

| 任务 | v1 train | v1 val |
|---|---:|---:|
| pcp | **100** | **0** |
| pob | 80 | 20 |
| 合计 | 180 | 20 |

**Val 集只有 pob，pcp 没有任何样本能做 out-of-sample 验证**——这是设计缺陷。

### 1.2 我们之前做的所有 inference / compare 都是 pob

之前 14D 后训练的 val inference（`pob_0084 / 0088 / 0099`）、6 联 quality 对比、推理时延对比，**全部是 pob**。pcp 的生成质量从来没在 out-of-sample 数据上验证过。

### 1.3 v2 目标

按 task 各自 90/10 切，让 train / val 同时覆盖两个任务：

| 任务 | v2 train | v2 val |
|---|---:|---:|
| pcp | 90 | 10 |
| pob | 90 | 10 |
| **合计** | **180** | **20** |

train 数量与 v1 完全一致（180），方便老实验 loss 数值对比；val 均衡覆盖两个任务。

pob 的 HDF5 完整保留，**没动**。

### 2.2 各类数据完整性

| 类型 | pcp | pob |
|---|---|---|
| 原始 HDF5 | ❌ 4 region 全删 | ✅ 100 个完整（region_all_clean） |
| 原始 mp4 视频 | ✅ 100 个完整（`video/episode*.mp4`） | ✅ 100 个完整 |
| 旧 cosmos JSON（v1）| ✅ 100 个（`/mnt/gyc_ckp/cosmos-predict2.5-robotwin/annotation/train/pcp_*.json`） | ✅ 100 个（80 train + 20 val） |
| 旧 cosmos 视频软链（v1）| ✅ 100 个 | ✅ 100 个 |

### 2.3 影响

由于 v1 的 pcp JSON 是从被删的 HDF5 算出来的（14D state 的 quat→euler 已经做完了），**v2 不需要重算 state**——直接复用 v1 的 pcp JSON 就行，state 数据完全一致。

也就是说：
- **pob 重新转 HDF5**（HDF5 在）：用脚本切 90/10
- **pcp 复用 v1 JSON**（HDF5 不在）：从老数据拷过来重切 90/10

## 三、v2 数据集设计

### 3.1 切分规则

```
pcp 100 个：前 90 → v2 train，后 10 → v2 val
pob 100 个：前 90 → v2 train，后 10 → v2 val
```

按文件名升序（`pcp_0000.json ... pcp_0099.json`），不打乱——这样 v2 train 中的 pcp 编号 `pcp_0000~0089` 是 v1 train 的子集，v2 val `pcp_0090~0099` 是 v1 train 的尾部 10 个。

### 3.2 路径

| 项 | 路径 |
|---|---|
| **v1 数据**（保留不动，老实验复现用） | `/mnt/gyc_ckp/cosmos-predict2.5-robotwin/` |
| **v2 数据**（新实验用） | `/mnt/gyc_ckp/cosmos-predict2.5-robotwin-v2/` |

V0.1 / V0.2 训练脚本将通过 Hydra CLI override 把 dataset 路径切到 v2。

### 3.3 数据内容

每个 JSON 字段（与 v1 一致）：
- `texts` — 任务描述（一句话）
- `videos` — 相对路径 `videos/{ep_id}.mp4`
- `state` — `[N, 14]`，14D dual-arm endpose `[l_xyz, l_rpy, r_xyz, r_rpy, l_g, r_g]`
- `continuous_gripper_state` — `[N]`，左右夹爪均值
- `episode_id` — `{prefix}_{idx:04d}`

视频是软链，指向原始 RoboTwin 仓库下的 mp4。

pcp 部分：

### 4.2 复用 v1 的 pcp JSON

不能从 HDF5 重转 pcp，从 v1 直接拷过来切：

```bash
SRC=/mnt/gyc_ckp/cosmos-predict2.5-robotwin
DST=/mnt/gyc_ckp/cosmos-predict2.5-robotwin-v2

# pcp 0000~0089 → v2 train（共 90）
for i in $(seq -f "%04g" 0 89); do
  cp $SRC/annotation/train/pcp_$i.json $DST/annotation/train/
done

# pcp 0090~0099 → v2 val（共 10）
for i in $(seq -f "%04g" 90 99); do
  cp $SRC/annotation/train/pcp_$i.json $DST/annotation/val/
done

# pcp 视频软链：直接拷源软链（指向同一个 .mp4）
for i in $(seq -f "%04g" 0 99); do
  cp -P $SRC/videos/pcp_$i.mp4 $DST/videos/
done
```

> ⚠️ JSON 里的 `videos[0].video_path` 是相对路径 `videos/pcp_XXXX.mp4`，**不需要修改 JSON 内容**——只要 v2 的 `videos/` 下有同名软链就行。

## 七、给训练脚本的改动

`cosmos_predict2/_src/predict2/action/configs/action_conditioned/data.py:219` 已经把 `robotwin_base_path` 改成 v2 路径：
