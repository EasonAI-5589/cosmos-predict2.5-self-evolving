## 一、关键洞察：Policy 的 value 不是 head，是 latent frame

最反常识的发现：

> **Cosmos Policy 没有独立的 value head 网络分支**。Value 是 DiT 主干处理的 latent sequence 里的**一帧**，模型用同一套去噪机制把它"生成"出来。

具体说，Policy 的 latent 时间维 `state_t = 9`，9 个 frame 的语义分配是：

| latent 帧 | 内容 |
|---:|---|
| 0 | blank frame（占位）|
| 1 | current proprio |
| 2 | wrist image |
| 3 | primary image |
| 4 | action chunk |
| 5 | future proprio |
| 6 | future wrist |
| 7 | future primary |
| **8** | **value（标量 broadcast 成 latent frame）** |

**Value 的"标量 → latent frame"映射**：把 value 标量 `[B]` reshape 成 `[B, C, H, W]`（通常是 broadcast 填充），塞到 latent sequence 第 8 帧位置。模型在去噪时预测整个 sequence，自然包含第 8 帧的 value。

**好处**：
- **不动 DiT 架构**，不加任何 nn.Module
- **复用所有 transformer block**，attention 内部自动让 value 和其他帧交互
- **训练 loss 复用**：扩散 MSE 自然包含 value 的 MSE

**对应的硬约束**：
- 需要扩 `state_t`（+1 给 value）
- 需要 dataset 提供 `value_function_return` 标量
- 需要 loss masking 区分"什么时候算 value loss / 什么时候只算视频 loss"

## 二、Policy value 实现深拆

### 2.1 Returns 怎么算

源文件：`cosmos_predict2/_src/predict2/cosmos_policy/datasets/dataset_common.py:25-55`

```python
def compute_monte_carlo_returns(num_steps, terminal_reward, gamma):
    rewards = np.zeros(num_steps)
    rewards[-1] = terminal_reward                  # 稀疏奖励，只在最后一步
    returns = np.zeros(num_steps)
    returns[-1] = rewards[-1]
    for t in range(num_steps - 2, -1, -1):
        returns[t] = rewards[t] + gamma * returns[t+1]    # 逆序折扣回推
    returns = 2 * returns / terminal_reward - 1   # 归一化到 [-1, 1]
    return returns
```

输入：
- `terminal_reward`：success rollout 时 = 1.0；failure = 0.0
- `gamma`：0.99（默认）

输出：每帧一个标量 returns，整个 episode `[T]`。

### 2.2 Returns 怎么进 dataset

`libero_dataset.py:912-919`（采样某一帧 `t` 时）：

```python
sample_dict["value_function_return"] = returns[t]    # 标量 float
```

LIBERO config（`cosmos_policy_experiment_configs.py:126-127`）：
```python
return_value_function_returns=True,
gamma=0.99,
```

### 2.3 Returns 怎么进模型

源文件：`cosmos_policy/models/policy_text2world_model.py:401-403`（`compute_loss_with_epsilon_and_sigma`）

```python
# value_function_return: [B] standalone scalar
# 转成 [B, C, H, W]（latent 平面），塞到 x0 的第 value_latent_idx (=8) 帧
x0[batch_indices, :, value_latent_idx, :, :] = value_function_return.reshape(B, 1, 1, 1).expand(...)
```

具体 broadcast 方式：把标量 broadcast 成 latent frame 的所有像素都等于这个 value（最简单的"value-as-frame"映射）。

### 2.4 Loss 怎么算

源文件：`policy_text2world_model.py:240-308`（`training_step`）+ `:310-700`（`compute_loss_with_epsilon_and_sigma`）

**统一的 EDM 扩散 loss**：
```python
pred_mse_B_C_T_H_W = (x0 - model_pred.x0) ** 2          # 整个 latent sequence 的 MSE
```

**关键是 loss masking**（`:413-561`）：根据 sample 类型决定哪些 frame 的 loss 算、哪些不算：

| Sample 类型 | 算 loss 的 frame |
|---|---|
| Demo（无 value）| 只算 action frame |
| World model | 只算 future state frame |
| **Value function** | **只算 value frame** |

Sample 类型在 dataset 层用概率分配（`demonstration_sampling_prob=0.5`, `success_rollout_sampling_prob=0.5`）。

Value loss 单独跟踪两个指标：
```python
value_function_sample_value_mse_loss
value_function_sample_value_l1_loss
```

### 2.5 Inference

不需要单独的 value forward。一次正常的 denoise 调用，输出 latent 的第 8 帧就是 value 预测。**取均值 / 中位数还原成标量**就是模型评估的 "V(s)"。

源文件：`policy_video2world_model.py:get_x0_fn_from_batch:747-770`

## 四、设计方案：把 value 当 latent frame 注入 AC

完全照搬 Policy 的"value-as-latent-frame"设计。

### 4.1 latent sequence 重新分配

在 AC 当前的 `state_t = 1 + chunk // 4` 基础上 **+1**，给 value 留位置：

| 配置 | 旧 state_t | 新 state_t | 多出来的 frame 含义 |
|---|---:|---:|---|
| chunk=12（v1 14D 训练）| 4 | **5** | 第 4 帧 = value |
| chunk=16（V0.1）| 5 | **6** | 第 5 帧 = value |
| chunk=32（V0.2）| 9 | **10** | 第 9 帧 = value |

**新 latent 语义（以 chunk=12 为例）**：
| latent 帧 | 内容 |
|---:|---|
| 0 | 条件帧（current image） |
| 1, 2, 3 | future video frames |
| **4** | **value frame**（标量 broadcast）|

### 4.2 Value 标量 → latent frame 映射

照抄 Policy：
```python
# returns 是 [B] 的标量
# tokenizer latent shape：[B, C=16, T, H'=H/8, W'=W/8]
B, C, _, Hp, Wp = x0.shape
x0[:, :, value_idx, :, :] = returns.view(B, 1, 1, 1).expand(B, C, Hp, Wp)
```

简单粗暴的 broadcast：value 标量填满整个 latent 平面。

### 4.3 Loss masking

新增一个 binary mask `[B, T]`，标记每个样本每帧是否参与 loss：

```python
# 训练时根据 sample 类型决定
if sample_type == "with_value":
    loss_mask = ones_like(...)              # 视频帧 + value 帧都算
elif sample_type == "video_only":            # 老 demo 没 value
    loss_mask[:, value_idx] = 0              # value 帧不算
```

总 loss = `Σ (mask × per_frame_mse) / Σ mask`。

### 4.4 推理时取出 value

```python
latent_pred = denoise(...)                    # [B, C, state_t, H', W']
video_latent = latent_pred[:, :, :video_T, :, :]   # 解码视频
value_latent = latent_pred[:, :, value_idx, :, :]  # [B, C, H', W']
value_scalar = value_latent.mean(dim=[1,2,3])      # [B]
# 反归一化（如果训练时归一化到 [-1,1]）
value_real = (value_scalar + 1) / 2 * terminal_reward
```

## 五、数据层面的硬约束

### 5.1 必须的字段

每个样本需要新增：
- `value_function_return`：`float` 标量（reduced from γ-returns 序列）
- 或 `returns`：`[T]` 序列（每帧一个，由 sample 起点决定取哪个）

### 5.2 RoboTwin 当前数据缺什么

我们 RoboTwin 转换出来的数据是**纯 demo**（成功示教），没有：
- ❌ failure rollout
- ❌ reward signal
- ❌ success/fail label

要算出 `compute_monte_carlo_returns()` 的输入 `terminal_reward`，至少需要 success/fail 二元标签。

### 5.3 三种数据方案

| 方案 | 做法 | 数据成本 | value 训练效果 |
|---|---|---|---|
| **A. Demo-only + 假装 success** | 全部 demo 都视为 success（terminal_reward=1.0），算出来的 returns 全部正、单调下降到 1.0 | 0（直接用现有 v1/v2）| ⚠️ value 无判别力 — 模型只学会"任何状态 value 都接近 1"，没用 |
| **B. Simulator rollout 重生成** | 用 RoboTwin simulator 跑 student policy / 随机 policy 收 success + fail rollout | 1-2 天工程（写 rollout 脚本 + 跑 simulator + 转格式）| ✅ 真正能训 value |
| **C. 时间到末端 proxy** | 用 `(1 - t/T_episode)` 当 value（越接近 episode 末端 value 越大），不用 reward | 0 | ⚠️ 学的是"到末端的距离"，不是 task value，但比方案 A 有判别力 |

**推荐组合**：
- **短期**（架构验证）：用方案 A 或 C，目标是把整套 pipeline 跑通，验证 value frame 能学（loss 能降）
- **长期**（真正可用）：方案 B，但要单独立项

### 5.4 关于 success/fail 信号

可能的来源：
- RoboTwin 仿真器在 episode 结束时有 `task_completed: bool` 标志（需要检查 hdf5 字段或 simulator return）
- 如果 demo 集本身就是"全 success"（一般 expert demo 是这样），那 fail 数据**必须**靠 simulator rollout 生成

## 七、实施阶段（建议）

### Phase 1：架构跑通（1-2 天）

**目标**：value frame 注入 + 输出能跑，loss 能降，**不要求 value 有意义**。

- 数据：用方案 C（时间 proxy value）或方案 A（全 success 假 value）—— 不用等真 reward 数据
- 复用 v2 数据集，加一个 `returns` 字段（脚本生成）
- 改 dataset、网络、loss
- 起一个小训练（1k iter），观察 value frame loss 是否下降

**Done 条件**：
- ✅ 训练能起来，没 crash
- ✅ value frame MSE loss 在前几百 iter 内可见下降
- ✅ inference 能 expose value scalar

### Phase 2：真实 value 训练（视情况）

**前提**：有 success/fail rollout 数据（方案 B）

- 写 RoboTwin rollout 脚本生成 success + fail
- 转成 v2 数据集格式 + 加 success flag
- 走 100k iter 完整训练
- 评估 value 的判别力（比较 success rollout vs fail rollout 的 value 分布）

### Phase 3：value-guided inference（可选）

- 在长序列推理时，用 value 选 chunk（多 chunk 候选 → value 高的留下）
- 类似 Cosmos Policy 的 best-of-N 评估机制

## 八、未决问题

1. **Value 标量 → latent frame 的 broadcast 方式**：Policy 用全像素填充同一个 scalar，这样 attention 看到 value 时是"常数图"。能不能用更紧致的编码（如 sinusoidal, MLP project）？需要试。

2. **要不要训练 demo + value 混合 sample**：Policy 用概率混合（50% demo / 50% rollout），AC 的 demo-only 数据如果要混 value，只能给假 value 或时间 proxy。

3. **state_t +1 对 RoPE 的影响**：现有 `rope_t_extrapolation_ratio=24/24=1.0` 是按 state_t=24 训出来的（基座）；扩到 state_t+1 是不是要重训 RoPE？预期影响小，但要验证。

4. **Inference 时 value 可信度**：从 latent broadcast frame reduce 回 scalar，怎么保证不噪？mean / median / 哪些维度 reduce？需要做小实验对比。

5. **跟 RoboTwin "no reward 数据" 这个根本约束怎么和解**：value 没有真信号训不出来。Phase 1 跑通架构后，**真训练必须等 simulator rollout 数据**，否则就是空架子。
