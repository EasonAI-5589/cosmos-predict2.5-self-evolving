# 15. Action-Conditioned 的 action 是位姿还是关节？

> 一句话结论：**用的是末端执行器位姿（end-effector pose / endpose），不是关节角度（joint）**。Bridge 官方如此定义，我们 RoboTwin 14D 双臂也沿用。本文档列出论文 + 代码的完整证据链，并说明为什么这么选、未来可不可以切换到 joint。

## 一、结论速查

| 项 | 值 |
|---|---|
| **单臂（Bridge 官方）** | 7 维：`[Δx, Δy, Δz, Δθ_r, Δθ_p, Δθ_y, GripperWidth]`（gripper 坐标系下的相对位姿变化 + 夹爪宽度）|
| **双臂（我们 RoboTwin）** | 14 维 = 左臂 7D + 右臂 7D（同上结构 × 2）|
| **本质** | **末端执行器位姿的相对变化**（end-effector pose delta）|
| **不是** | 关节角度（joint position），也不是关节角度变化 |

**总结**：整个 Cosmos-Predict2.5 AC 系列（Bridge 单臂、我们 RoboTwin 双臂）的 action **从来不是 joint**，全是 endpose。

## 二、Bridge 官方 7D 定义（原文）

### Cosmos-Predict2.5 论文 Section 6.6 原文

> The dataset contains approximately 20,000 episodes [...] Each video has a resolution of 320 × 256 and is recorded at 5 FPS. Corresponding to each frame, the robot action is represented as a **7-dimensional vector in the gripper coordinate space**: `(Δx, Δy, Δz, Δθ_r, Δθ_p, Δθ_y, GripperWidth)`, which specifies the **relative displacement, rotation, and width of the gripper**.

来源：[`arxiv 2511.00062`](https://arxiv.org/abs/2511.00062) Cosmos-Predict2.5 技术报告 §6.6

### 逐维拆解

| 维度 | 字段 | 坐标系 | 单位 | 含义 |
|:-:|---|---|---|---|
| 0 | Δx | gripper 前一帧坐标系 | 米（×20 缩放）| 位置增量 x |
| 1 | Δy | 同上 | 米（×20） | 位置增量 y |
| 2 | Δz | 同上 | 米（×20） | 位置增量 z |
| 3 | Δθ_r | 同上 | 弧度（×20） | roll（欧拉角）增量 |
| 4 | Δθ_p | 同上 | 弧度（×20） | pitch 增量 |
| 5 | Δθ_y | 同上 | 弧度（×20） | yaw 增量 |
| 6 | GripperWidth | — | 0-1 连续值 | 夹爪开合度（0=开，1=闭） |

**关键点**：
- 前 6 维是**相对 last frame 的 SE(3) 变换**，不是绝对位姿
- 旋转用 roll/pitch/yaw 欧拉角表示（不是四元数、不是旋转矩阵）
- 第 7 维是**绝对**夹爪宽度（**不是**相对变化）

## 三、我们 RoboTwin 14D 双臂的实现

### 数据转换：从 HDF5 读哪个字段

文件：`scripts/convert_robotwin_to_cosmos.py:47-50`

```python
with h5py.File(hdf5_path, "r") as f:
    left_endpose  = f["endpose/left_endpose"][:]   # (N, 7) ← 读 endpose
    right_endpose = f["endpose/right_endpose"][:]  # (N, 7)
    left_gripper  = f["endpose/left_gripper"][:]   # (N,)
    right_gripper = f["endpose/right_gripper"][:]  # (N,)
```

**只读 `endpose/*` 路径下的字段，`joint_action/*` 没被读**。

### endpose 是什么格式

每一帧 7 维：`[x, y, z, qw, qx, qy, qz]`（xyz 位置 + **四元数**旋转），**世界坐标系下的绝对末端位姿**。

### 转成 Cosmos 格式时做的处理

1. **四元数 → 欧拉角**（为了和 Bridge 的欧拉角表示对齐）
   ```python
   def quat_to_euler(endpose):
       xyz  = endpose[:3]        # 位置
       quat = endpose[3:]        # [qw, qx, qy, qz]
       rotm = t3d.quaternions.quat2mat(quat)
       rpy  = t3d.euler.mat2euler(rotm, axes='sxyz')   # [roll, pitch, yaw]
       return np.concatenate([xyz, rpy])   # (6,): [x, y, z, r, p, y]
   ```

2. **左臂 6D + 右臂 6D + 左右夹爪 2D = 14D state**，存进 JSON
   ```python
   state[i] = [
       *quat_to_euler(left_endpose[i]),    # (6,) 左臂 xyz+rpy
       *quat_to_euler(right_endpose[i]),   # (6,) 右臂 xyz+rpy
       left_gripper[i], right_gripper[i],  # (2,) 左右夹爪
   ]
   # 总 14 维
   ```

### 训练时 action 怎么算（从 state 派生）

文件：`cosmos_predict2/_src/predict2/action/datasets/dataset_local.py:322-340`（dual-arm 分支）

```python
def _get_actions(self, arm_states, gripper_states, accumulate_action):
    # arm_states: (T, 12)，左臂 6 + 右臂 6
    # gripper_states: (T, 2)
    left_arm = arm_states[:, :6]    # (T, 6)
    right_arm = arm_states[:, 6:12]
    for k in range(1, sequence_length):
        # 左臂：在前一帧 gripper 坐标系下的相对变换
        prev_rotm_l = euler2rotm(left_arm[k-1, 3:6])
        rel_xyz_l = np.dot(prev_rotm_l.T, left_arm[k, 0:3] - left_arm[k-1, 0:3])
        rel_rpy_l = rotm2euler(prev_rotm_l.T @ euler2rotm(left_arm[k, 3:6]))
        # 右臂：同理
        prev_rotm_r = euler2rotm(right_arm[k-1, 3:6])
        rel_xyz_r = np.dot(prev_rotm_r.T, right_arm[k, 0:3] - right_arm[k-1, 0:3])
        rel_rpy_r = rotm2euler(prev_rotm_r.T @ euler2rotm(right_arm[k, 3:6]))
        # 14D action
        action[k-1] = [
            *rel_xyz_l, *rel_rpy_l, gripper_states[k, 0],   # 左臂 7D
            *rel_xyz_r, *rel_rpy_r, gripper_states[k, 1],   # 右臂 7D
        ]
```

### 14D 逐维说明

| 索引 | 含义 |
|:-:|---|
| 0-2 | 左臂位置增量 `[Δx_l, Δy_l, Δz_l]` |
| 3-5 | 左臂旋转增量（欧拉角）`[Δθ_r_l, Δθ_p_l, Δθ_y_l]` |
| 6 | 左夹爪宽度 |
| 7-9 | 右臂位置增量 `[Δx_r, Δy_r, Δz_r]` |
| 10-12 | 右臂旋转增量 `[Δθ_r_r, Δθ_p_r, Δθ_y_r]` |
| 13 | 右夹爪宽度 |

**100% 和 Bridge 单臂 7D 同构**，只是双臂各一份。

### scaler

`dataset_local.py:149-151`：
```python
self.c_act_scaler = [20., 20., 20., 20., 20., 20., gripper_rescale_factor,   # 左臂
                     20., 20., 20., 20., 20., 20., gripper_rescale_factor]   # 右臂
```
**位置和姿态增量 × 20**（原始值通常毫米级 0.001，×20 放大到 0.02 级让网络更敏感），**夹爪 × 1**（宽度本来就是 0-1）。

## 四、RoboTwin HDF5 里其实两套数据都有

RoboTwin 原始 HDF5 存了两套并列的数据：

| 路径 | 字段 | shape | 语义 |
|---|---|---|---|
| **`endpose/*`** | `left_endpose`, `right_endpose` | `(N, 7)` | 末端位姿 xyz+quat（**我们用的**）|
| `endpose/*` | `left_gripper`, `right_gripper` | `(N,)` | 夹爪连续值（**我们用的**）|
| **`joint_action/vector`** | — | `(N, 14)` | 关节角度（6 左臂关节+1 左夹爪 +6 右臂关节+1 右夹爪，**我们没用**）|
| `joint_action/*` | `left_arm`, `right_arm`, `left_gripper`, `right_gripper` | `(N, 6)`, `(N, 6)`, `(N,)`, `(N,)` | 同上的分字段版 |

**我们完全没读 `joint_action/*`**，14 维碰巧跟 `joint_action/vector` 的 14 维一样但含义完全不同：
- `joint_action/vector` 是 14 个**关节角度**
- 我们的 14D action 是 2 × (3 位置 + 3 欧拉角 + 1 夹爪) 的**末端位姿组合**

## 五、为什么选位姿不选关节

### 理由 1：和 Bridge 对齐，共用 pipeline

- Bridge 是 Cosmos AC 官方参考实现（`robot/action-cond` 用它训）
- Bridge 用 7D endpose，我们用 14D endpose（维度翻倍，结构一致）
- Dataset / network / loss 等代码都是从 Bridge 分支过来的，换 joint 语义就要大改

### 理由 2：视频 ↔ action 的语义对应更直接

- 视频像素上看到的是**末端在 3D 空间的移动** —— 跟 endpose 直接对应
- 关节角度的变化→ 3D 末端位置的映射是**非线性**的（forward kinematics），模型学起来多一层间接
- 同样动作目标（比如"抓杯子"），不同机器人末端位姿相同但关节配置可能完全不同

### 理由 3：跨机器人泛化更容易

- endpose 是机器人无关的表示（任何 6-DoF 机械臂末端都是 xyz+rpy）
- 关节数依赖于机器人（6 关节 / 7 关节 / 不同机器人关节 limits 不一样）
- Cosmos 想做"通用机器人世界模型"，endpose 更通用

### 理由 4：相对变换 + gripper 坐标系的特殊设计

- 绝对位姿数值变化范围大（`x ∈ [-1, 1]`），相对变换范围小（`Δx ∈ [-0.01, 0.01]`），更适合网络学习
- 在 gripper 坐标系下（不是世界坐标系），旋转的 pitch/roll/yaw 增量有明确物理意义（"向前"、"绕手腕转"等），网络更容易建立 action ↔ 视觉对应关系

## 六、切换到 joint 的代价与收益

如果未来想换成 joint 表示（`joint_action/vector`），需要改的东西：

### 代价

| 环节 | 改动 |
|---|---|
| 数据转换 | `convert_robotwin_to_cosmos.py` 改读 `joint_action/vector` 而不是 `endpose/*` |
| State 字段定义 | state 语义从 "xyz+rpy+g" 改成 "关节角度"；quat_to_euler 不用了 |
| `Dataset_3D._get_actions` | 不再做相对变换，直接把连续帧的 joint 差分当 action |
| scaler | `c_act_scaler` 要重调（关节数值范围跟位置/旋转不一样）|
| Teacher ckpt 不兼容 | 已有 `iter_000150000/model_ema_bf16.pt` 的 action MLP 权重是按 endpose 训的，换 joint 就得重训（或者 `strict_resume=False` 丢掉 MLP）|
| 跟 Bridge 对比失效 | 没法直接跟 Bridge 7D baseline 做 sanity check |

### 收益

- **精确对应 Cosmos Policy 的 "joint pos + gripper" 要求**（如果我们要复刻 Policy 的 V0.x 设置）—— 见 doc 14 Phase 2 讨论
- 对于**仿真场景**来说，joint 是 simulator 直接可控的量（endpose 要 IK 反解）
- 如果下游任务是 joint-space policy（比如 LIBERO），action 用 joint 可以少一次 endpose ↔ joint 转换

### 最终建议

**现在用 endpose 14D（保持现状）**，等到真要对接 Policy 框架（加 value head 并且要跟 LIBERO policy 同构）时再切 joint。

届时可能需要：
- 重新写一版 `convert_robotwin_to_cosmos_joint.py`，输出路径 `cosmos-predict2.5-robotwin-v3-joint/`
- 重训 AC teacher（不能用现有的 14D endpose ckpt）

**短期内不建议切换** —— 我们现在用 endpose 跑的所有实验（V0.1 / V0.2 / V0.1.1 / V0.2.1）都是一致的，切换会引入大的 confound。
