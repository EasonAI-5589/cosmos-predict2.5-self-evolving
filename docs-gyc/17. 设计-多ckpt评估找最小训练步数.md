# 设计 —— 多 ckpt 评估找最小训练步数

## 动机

训练都按 100k iter 跑太浪费。需要系统化判断：
- **收敛点**：loss 和视频质量什么时候真的趋平？后面多训是不是无用功？
- **够用点**：哪一个 step 的 ckpt 就能达到"够用"的质量（比 100k 结果差 X% 以内）？
- **quality 趋势**：training loss 降了，生成质量一定更好吗？AC 模型里 loss 降 ≠ action-video 对齐变好。

一旦有这套评估，后续所有实验可以用 **"在 quality 曲线拐点之后 1-2 个 ckpt"** 作为早停依据，节省大量 GPU 时间。

## 现状盘点

- **Ckpt 密度充足**：`save_iter=1000`，V0.1 已有 50 个 ckpt（iter 2k-100k，每 2k 一个），V0.1.1/V0.2.1 在涨。
- **Val 集可用**：v2 `/mnt/gyc_ckp/cosmos-predict2.5-robotwin-v2/annotation/val` 20 条（10 pcp + 10 pob）。
- **推理入口**：`cosmos_predict2/action_conditioned.py` + `examples/inference.py`；当前 `scripts/inference_local.sh` 是单 ckpt 模式。
- **评估库缺**：环境里没装 `lpips` / `piq` / `torchmetrics`，需要补。

## 评估指标（分三层，逐层加）

### Layer 1 —— 像素级（必做，便宜）
- **PSNR**：生成视频 vs GT 视频，逐帧 mean。
- **SSIM**：逐帧 mean，对结构相似性敏感。
- **LPIPS**（VGG/AlexNet backbone）：学习到的感知距离，比 PSNR/SSIM 更接近人眼判断。

**复杂度**：对每个 (ckpt, val_sample) 产出 1 个数。val=20、16-frame 情况下，一个 ckpt 全 val 算一次 <1 分钟。

### Layer 2 —— 分布级（可选，要 N>50 才稳）
- **FVD**（Fréchet Video Distance）：用 I3D backbone 提特征，比较生成分布 vs GT 分布。
- 注意：val 只有 20 条时 FVD 噪声大，要跑 batch 生成（同一个 ckpt 对同一 label 多次采样）或扩大 val 集。

**判断**：V0.1 阶段先跳过 FVD，等 pipeline 稳了再加。

### Layer 3 —— AC 特有（**最关键**，自研）
- **Action-Trajectory Consistency**：生成视频里**末端执行器位置**的估计轨迹 vs input action 的期望轨迹，算 MSE。
  - 实现路径：用 RoboTwin 的 camera intrinsic + hand-eye calib 反投影 action 到像素空间，做模板匹配或用 SAM 分割 gripper mask → 得到像素位置 → 累加位置差。
  - 更轻量版本：先用**光流一致性**——生成视频的光流 flow map 应该和 GT video 的 flow map 近似（同样的 action 条件应产生同样的运动）。算 flow 间 EPE (end-point error)。
- **Gripper State Accuracy**：生成视频里 gripper 开/闭状态 vs action 里 gripper bit 的一致率。需要分类器，但 RoboTwin 的 gripper 黄色很显眼，简单颜色阈值足够。

**判断**：Layer 3 是 AC 模型评估最有意义的指标——**loss 平了、PSNR 高了，但 action 对不上也没用**。先跑 Layer 1 + 光流版 Layer 3 最低配。

## Ckpt 采样策略

### 阶段一：V0.1 回溯验证（先一次性跑通）
用 **log 间距** 9 个 ckpt：`[2k, 5k, 10k, 20k, 35k, 50k, 75k, 100k]`（V0.1 100k 已全量存盘）。
- 早期密（1-10k 变化快）
- 中期稀（20-50k 观察收敛）
- 后期稀（75k, 100k 看是否还在下降）

### 阶段二：新实验在线评估
`every_n_save` 保持 1000，但 `eval_ckpts.py` 跑起来只拉 log 间距的 ckpt，不每个都评估。

## eval_ckpts.py 架构

```
eval_ckpts.py
├── CLI args
│   --run-dir           # e.g. .../robotwin_14d_v01_16f_224_8gpu
│   --ckpt-iters        # list, 默认 [2000, 5000, 10000, 20000, 35000, 50000, 75000, 100000]
│   --val-dir           # val annotation dir
│   --n-val-samples     # 默认 20（全 val）
│   --num-inference-steps  # 默认 35（与 teacher 对齐）
│   --output-dir        # 存每个 ckpt 的生成视频 + metrics.json
│   --metrics           # list ["psnr", "ssim", "lpips", "flow_epe"]
│   --wandb-run-id      # 如指定，把指标 merge 回原 wandb run (step 轴)
│
├── 主循环（每 ckpt 一次）
│   1. load_ckpt(run_dir / "checkpoints/iter_XXXXXX")
│   2. for sample in val_loader:
│        gen_video = inference(model, sample)  # 基于 action_conditioned.py 抽出
│        save_video(gen_video, output_dir / ckpt_id / sample_id)
│   3. metrics = compute_all_metrics(gen_videos, gt_videos)
│   4. dump(metrics.json)
│   5. (optional) wandb.log(metrics, step=ckpt_iter)
│
└── 汇总
    - 输出 CSV：iter, psnr, ssim, lpips, flow_epe
    - 输出 plot：quality-vs-step 叠加 train_loss（副 y 轴）
```

### 关键解耦
1. **Inference** 独立成一个函数，从 `action_conditioned.py` 抽出核心逻辑（不走 CLI），接受 `model_path + sample_dict` 返回 `(B, T, H, W, C)` numpy。这样可以被 loop 调用。
2. **Metrics** 独立模块 `metrics/`，每个指标一个 file，都实现 `compute(pred: np.ndarray, gt: np.ndarray) -> float`。LPIPS / FVD 用 lazy import。
3. **Wandb 回写**：用原 run_id `wandb.init(id=..., resume="must")` 续上之前的 loss 曲线，新指标作为额外 series 写到同一 step。这样 wandb 单图就能看 loss + quality。

## 判断"收敛点"的标准

三选二满足即可认为后续训练是浪费：
1. **Train loss**：过去 10k iter 的 slope < 1e-6 / iter（几乎平）
2. **PSNR / SSIM**：过去 20k iter 内增幅 < 1%
3. **LPIPS / Flow-EPE**：过去 20k iter 内改善 < 5%

### 实际输出
对每个实验产出一份 `ckpt_analysis.md`：
- quality-vs-step 曲线
- 标注"建议停在 iter X"（基于上述规则）
- 对应 X 的 ckpt 路径 + 最终 quality vs 100k 的差异 %

## 风险与取舍

- **Val 集太小（20 条）→ 指标方差大**：先用固定 seed + 多 ckpt 的相对变化趋势判断，不比较绝对值；必要时扩 val 到 50-100 条。
- **Inference 耗时**：V0.1 单样本 35 步 denoising 约 10-20s（未蒸馏），8 ckpt × 20 val = 160 次 × 15s ≈ 40min，可接受；32-frame 的 V0.2 系列 × 2 → ~80min；蒸馏后 4 步 → 5min 一轮。
- **GT video 和生成帧数对齐**：V0.1 生成 17 帧，V0.1.1 因 value frame 会 decode 21 帧，评估时需要 strip。正好可以作为动机推 Phase 0 的 `action_conditioned.py` inference 改造。
- **指标会骗人**：LPIPS 高可能只是颜色整齐，和 motion 质量无关。**一定要 Layer 3**。
