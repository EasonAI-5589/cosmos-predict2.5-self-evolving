# 18. Value 评估 — 当前闭环实现（V0.1.1 现状）

> 把现在 V0.1.1（16 帧 + value）从训练 GT、模型架构、推理 loop 到可视化的完整链路写清楚。这是「现状文档」，不提优化——优化思路见 `19. Value优化-按翔哥Comment重设计.md`。

---

## 一、TL;DR

- **训练 GT**：每个 sample 取一个标量 `returns_seq[fids[0]]`——条件帧（chunk 起点）对应的 Monte-Carlo returns
- **模型表达**：value 不走独立 head，而是作为 latent sequence 末尾**多出来的一帧**（broadcast 标量到 `[C, H', W']`），跟视频 latent 在同一个 DiT 里联合去噪
- **推理 loop**：闭环 chunk 串行——每 chunk 用上一 chunk 模型生成的最后一帧当 cond，每 chunk 出 1 个 V 标量
- **结果形态**：一条 200 帧 episode → ~12 个 V 台阶；4 白名单样本上 V 单调从 -0.6 上升到 +0.6

---

## 二、训练侧：GT 怎么取

源文件：`cosmos_predict2/_src/predict2/action/datasets/dataset_local.py:225-287`

### 2.1 episode 级 returns 序列

每条 episode 加载时，按蒙特卡洛回推算一遍 returns（参考 Cosmos Policy 的 `compute_monte_carlo_returns`）：

```python
# dataset_local.py:236-244
if self.return_value_function_returns:
    success = ann.get("success", self.success_default)   # demo-only 数据 success_default=True
    terminal_reward = 1.0 if success else 0.0
    returns_seq = compute_monte_carlo_returns(
        num_steps=n_frames,
        terminal_reward=terminal_reward,                  # 1.0
        gamma=self.gamma,                                  # 0.99
    )
    # 输出：长度 = n_frames 的 ndarray，[-1, 1] 归一化
```

直觉：成功 episode 的 returns_seq 是 **从 ~-1 单调上升到 +1 的指数曲线**，越接近 episode 末端 returns 越大。失败 episode 的 returns_seq 全是 -1（terminal_reward=0 → returns=-1），但当前 RoboTwin 数据**全部是 demo（成功）**，所以实际只走 `terminal_reward=1.0` 这条路径。

### 2.2 单 sample 的 GT 标量

V0.1.1 用 `n_value_frames=1`，每个 sample 一个标量：

```python
# dataset_local.py:263-265
if self.n_value_frames == 1:
    sample["value_function_return"] = float(returns_seq[fids[0]])
    #                                                  └─ chunk 起点 = 条件帧
```

`fids[0]` 是该 sample 的**条件帧索引**（17 帧 sample 里的第 0 帧；后面 16 帧 = 要预测的 future）。

> **关键澄清**：V0.1.1 的 GT 已经对应「输入帧」，**不是**「下一 chunk 末帧」。N>1 的 V0.1.5 GT 取 `fids[1..]` 才是生成帧位置——区别详见文档 19。

### 2.3 训练时 sample 类型混合

当前 RoboTwin 数据 100% 是 demo，没有 sample type 区分（不像 Policy 用 `demonstration_sampling_prob` / `success_rollout_sampling_prob`）。每个 sample 都自带 value GT，无 mask。

## 三、模型侧：value 不是 head，是一帧

源文件：
- 配置：`cosmos_predict2/_src/predict2/action/configs/action_conditioned/experiment/exp_2B_action_conditioned_rectify_flow.py`
- 网络：`cosmos_predict2/_src/predict2/action/networks/action_conditioned_minimal_v1_lvg_dit.py`
- 模型逻辑：`cosmos_predict2/_src/predict2/action/models/action_conditioned_video2world_rectified_flow_model.py`

### 3.1 latent 序列布局

V0.1.1 配置（chunk=16, n_value_frames=1）：

| latent 帧 idx | 内容 | shape |
|---:|---|---|
| 0 | 条件帧（current image） | `[C=16, H'=H/8, W'=W/8]` |
| 1, 2, 3, 4 | future video frames（4 个 latent ↔ 16 像素帧）| 同上 |
| **5** | **value frame**（标量 broadcast）| 同上 |

`state_t = 1 + chunk//4 + n_value_frames = 1 + 4 + 1 = 6`。

### 3.2 标量 → frame 的 broadcast

`Video2WorldRectifiedFlowModel._maybe_append_value_frame`：

```python
# 标量 returns: [B]
# 目标 latent: [B, C, T+1, H', W']
B, C, _, Hp, Wp = x0.shape
value_latent = returns.view(B, 1, 1, 1, 1).expand(B, C, 1, Hp, Wp)  # 全像素 = 同一标量
x0 = torch.cat([x0, value_latent], dim=2)                            # cat 在 T 维末尾
```

直白说：value 标量填满 `C × H' × W'` 个 cell（最简单的 value-as-frame 编码）。

### 3.3 训练 loss

完全复用 rectified flow 的 velocity-MSE，**不**做 frame-level masking（跟 Policy 不同）：

```python
# text2world_model_rectified_flow.py
per_instance_loss = ((vt_pred - vt_target) ** 2).mean(dim=...)
loss = (time_weights * per_instance_loss).mean()
```

整个 latent sequence（6 帧）一起算，value 帧自然贡献 1/6 的 loss。loss=0.0053 的 V0.1.1 ckpt 也包含 value 帧的 MSE。

### 3.4 推理：从 value latent 取标量

`Video2WorldRectifiedFlowModel.get_value_from_latent`：

```python
# 完整 denoise → latent_pred [B, C, 6, H', W']
value_latent = latent_pred[:, :, -1, :, :]    # 最后一帧
value_scalar = value_latent.mean(dim=[1, 2, 3])   # 全部 reduce → [B]
```

mean reduce 是为了把 broadcast 时的"全部相同"逆回来；实测 value latent 内部还是会有些 noise（denoise 不完美），所以用 mean 而非任意单点。

## 四、推理侧：闭环 chunk 串行

源文件：`cosmos_predict2/action_conditioned.py:481-563`

### 4.1 chunk loop 结构

```python
# action_conditioned.py:469
img_array = action_data["initial_frame"]    # ← 第 0 chunk 的 cond，来自 dataset 真帧

for i in range(start_frame_idx, len(actions), chunk_size):    # 步长 = 16
    actions_chunk = actions[i : i + 16]                       # GT action（来自 dataset）

    # 把 cond 帧拼进 [1, C, T=17, H, W] 的 video 输入
    img_tensor = to_tensor(img_array).unsqueeze(0)
    vid_input = cat([img_tensor, zeros(16)], dim=0)

    # 完整 denoise + decode + 取 value
    video, predicted_value = generate_vid2world(
        input_path=vid_input,
        action=actions_chunk,
        return_value=True,
        num_steps=35,
        ...
    )

    # ─── 闭环关键 ───
    next_img_array = video[-1]          # 上一 chunk 模型生成的最后一帧
    img_array = next_img_array          # 作为下一 chunk 的 cond

    chunk_video.append(video)
    chunk_values.append(V_scalar)
```

定位：
- `action_conditioned.py:481` 步长 `chunk_size=16`
- `action_conditioned.py:531-533` 反馈赋值

### 4.2 一条 episode 输出

| 输出 | 内容 | 数量级 |
|---|---|---|
| `{ep}_chunk.mp4` | 拼接所有 chunk 的视频，~T 帧 | 200 帧左右 |
| `{ep}_value.json` | `{"chunk_size":16, "n_value_frames":1, "values":[V_0..V_{N-1}]}` | N ≈ T/16 ≈ 12 |
| `{ep}_with_value.mp4` | 视频 + 阶梯 V 曲线左右拼接 | 同上 |

### 4.3 闭环带来的特性

1. **误差累积**：第 k 个 chunk 的 cond 是前 k-1 chunk 错误的累积。视频生成漂 → cond 不在 manifold → V 跟着不可信。
2. **粗粒度 V**：T 帧的 episode 只有 ~T/16 个 V 标量，chunk 内部分辨率 = 0。
3. **末 chunk pad 反向跌**：episode 结尾 action 不足 16 时 zero-pad 凑齐，导致 ΔV 方向反转（实测 -0.12 ~ -0.25），是拼接问题不是 value head bug（已记录在 V0.1.1 实验文档）。

## 七、当前实现的局限

总结成 4 点（紧扣下一份优化文档要解决的问题）：

1. **闭环 cond 漂**：视频生成质量决定了 V 是否可信，二者纠缠在一起，没法单独诊断 value head
2. **粗粒度阶梯**：每 chunk 一个 V，看不到 chunk 内 progress 变化（V0.1.5 N=4/8/16 也只是"chunk 内多 N 个标量"，没解决根本）
3. **没有失败对照**：训练数据 100% 是 demo + terminal_reward=1.0；推理也只在 demo 上测；**判别力没有任何证据**
4. **GT 语义**：N=1 已经对齐输入帧（`fids[0]`），但翔哥 comment 暗示要更彻底——独立 value-only 模型，不被视频生成"分神"
