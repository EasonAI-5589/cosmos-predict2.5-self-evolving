# 19. Value 优化 — 按翔哥 Comment 重设计

> 前置阅读：`18. Value评估-当前闭环实现.md`（V0.1.1 现状）。
>
> 本文档基于飞书 4/27 文档 Todo 3 节翔哥的评审 comment，把现状的 4 个局限（闭环 cond 漂 / 粗阶梯 / 无失败对照 / GT 与视频生成纠缠）重设计成新方案，分**评估侧**（不重训）和**训练侧**（重训）两条线推进。

## 一、评审 Comment 原文 + 解读

飞书 Todo 3 节，翔哥列了 4 条：

| # | 原话 | 落到代码 |
|---|---|---|
| 1 | 直接把数据集的每一帧输入进入，每一帧只拿 value，每一步稠密的 value 曲线，每一帧都要对应一个 value | **评估改开环**：cond 帧来自 dataset 而非模型生成；**步长 1 而非 16**；只读 value 不解码视频 |
| 2 | 测试时不仅是数据集，失败轨迹和成功轨迹，拿给 cosmos-predict 的 value 去测效果 | 加**失败 rollout** 测试集 |
| 3 | 多训一个 predict value 的模型，当前是对下一个 chunk 的最后一帧打 value，但是新的训练应该监督改成当前输入帧对应的 value | **重训**：独立 value-only 头/模型，监督目标 = 输入帧 V(s_t) |
| 4 | Value GT 从 action 生成视频最后一帧的 index 换成数据集输入的初始帧 | 同 3，GT 取 `returns_seq[fids[0]]` 而非 `fids[-1]` |

> **现状对照**（详见文档 18）：N=1 的 V0.1.1 dataset 已经在用 `returns_seq[fids[0]]`（条件帧/输入帧）作为 GT。但翔哥 comment 3 说"当前是对下一个 chunk 的最后一帧打 value"——**指的是 N>1（V0.1.5）的实现**，因为 V0.1.5 GT 取 `fids[1..]`（生成帧位置）。所以 comment 3+4 的硬约束在 V0.1.1 上**已经满足**；要解决的是更彻底的「value 与视频生成解耦」——独立 value-only 模型，避免 value latent 被视频生成的 attention 分神。

把 4 条按工作量分组：

- **A. 评估侧（不重训，1-2 天）**：comment 1 + 2
- **B. 训练侧（重训，几天到一周）**：comment 3 + 4 → 独立 value-only 模型

## 二、A. 评估侧：开环稠密 + 失败轨迹

### 2.1 闭环 → 开环：核心改动

跟文档 18 的 `action_conditioned.py:481-534` 闭环 loop 对比：

| | V0.1.1 闭环 | 新 开环 |
|---|---|---|
| chunk 步长 | 16（每次跳 16 帧） | **1**（每帧一个起点） |
| cond 帧来源 | 上一 chunk 模型生成最后一帧 `video[-1]` | **dataset 真帧 `video[t]`** |
| action chunk | dataset GT actions[i:i+16] | dataset GT actions[t:t+16] |
| 是否 decode 视频 | 是（用于拼 mp4 + 取下一 cond） | **否**（只读 value latent，省 tokenizer 时间）|
| 输出 V 数 | T/16（~12 个） | **T-16（~184 个）** |

伪代码：

```python
for t in range(0, T - chunk_size):
    cond_frame = video_gt[t]                         # ← 开环：GT 帧，永远不漂
    actions_chunk = actions_gt[t : t + 16]
    _, V_t = model.forward(cond_frame, actions_chunk,
                           return_value=True, decode=False)  # 跳 decode
    dense_values.append(V_t)
```

### 2.2 复用 V0.1.1 ckpt

不重训。V0.1.1 的 value head 学的本来就是 `returns_seq[fids[0]]`——「输入帧 V(s_t)」——直接喂 GT 帧 + GT action chunk，输出就是该帧的 V 估计。

### 2.3 实施

**新增脚本** `scripts/workflow/dense_value_eval.py`（也可以直接在 `action_conditioned.py:inference()` 加 `--mode dense_value` 分支）：

| 步骤 | 实现 |
|---|---|
| 1. 加载 ckpt + 4 白名单 ann | 复用 `Video2WorldInference` + `_load_robotwin_action_fn` |
| 2. 替换 chunk loop step（16 → 1） | 把 `range(start, T, 16)` 改成 `range(0, T-16, 1)` |
| 3. cond 改 GT 帧 | 删掉 `img_array = next_img_array`，每步重新从 `video_gt[t]` 取 |
| 4. 跳过 decode | 给 `generate_vid2world` 加 `decode_video=False`，或外面包装跳过 tokenizer 那步 |
| 5. 落 json | `{"stride":1, "values":[V_0..V_{T-17}]}` 到 `outputs/dense_value_eval/{ep}_dense_value.json` |

**性能预算**：

- 单帧推理 ≈ 35 denoise step × 0.14 s ≈ **5 s**（H100，batch=1，跳 decode 后）
- 一条 200 帧 episode：184 × 5 s ≈ **15 min**
- 4 白名单全跑：约 **1 h**

加速档位（按风险从低到高）：

1. **batch 多个 t**：batch=4-8 应该能塞下，**4-8× 加速**。每个 sample 内部 RoPE 时间维度独立，不冲突
2. **降 denoise steps**：value 是 broadcast 标量，可能 5-10 步就稳。先扫 step={5,10,20,35} 看 V 是否漂，定阈值。**3-5× 加速**
3. **跳 tokenizer decode**：~20% 加速（已计入预算）

### 2.4 失败轨迹（comment 2 的硬条件）

当前 RoboTwin 数据 100% 是成功 demo，**没有 failure rollout**。要做"成功 vs 失败"对比必须先收数据。

| 来源 | 怎么拿 | 工程量 |
|---|---|---|
| **A. RoboTwin sim + random policy** | 写 rollout 脚本，policy = `random_action`，在 pcp/pob 任务上跑到失败 | ~1 天 |
| **B. RoboTwin sim + perturbed expert** | 在 demo expert 基础上加 noise（动作扰动 / 时序错位），收 ~30 条失败 | ~1 天 |
| **C. 截断现有 demo** | 直接砍掉 demo 后半段，假装 truncate at success—— 但这是 partial success 不是 failure | ~1 h，**判别力存疑** |

推荐 **B**：扰动 expert 的失败更接近真实 policy 失败模式。流程：

1. 写 `scripts/data_gen/collect_robotwin_failures.py`：调 RoboTwin sim，policy = expert + Gaussian noise(σ=0.2)
2. 收 ~30 条 failure（每任务 15 条），转成跟 v2 同 schema：`{ann.json, video.mp4, hdf5}`，但 `ann["success"]=False`
3. 走同一 dense eval 脚本

### 2.5 可视化

扩展 `scripts/workflow/visualize_value_curve.py`：

- 双曲线：橙色 = `V_gt = returns_seq`（dataset 算的真值），蓝色 = `V_pred`（模型输出）
- 横轴改 dataset 帧 idx（不再是 chunk idx）
- 失败 / 成功叠图：同任务内 success（绿）+ failure（红）画到一张图，看 V 是否分开

### 2.6 判别力指标

成功 vs 失败在三个维度看：

| 指标 | 期望 |
|---|---|
| 末端 V 差（success final V − failure final V） | ≥ 0.5 才有判别力 |
| 同 t 同任务下 success/failure V 分布 | KS 检验 p < 0.05 / 简单 mean±std 不重叠 |
| V 与 GT returns 的 Pearson 相关 | success 上 ≥ 0.8（学到了 progress），failure 上不要求 |

### 2.7 Done 条件

- [ ] `dense_value_eval.py` 跑通，4 白名单 episode 各产出 `{ep}_dense_value.json`
- [ ] 双曲线对比图（V_pred vs V_gt）出 4 张
- [ ] 至少 1 任务收齐 ~15 条 failure rollout，转好 schema
- [ ] 成功 vs 失败 V 曲线叠图，给出"有 / 没有"判别力的明确结论
- [ ] 把结果写进 `实验记录/V0.1.1-16f-with-value.md` 末尾"开环稠密评估"小节

如果开环跑出来 V 还是无脑单调上升、success 跟 failure 完全分不开 → 直接确诊「V0.1.1 的 value 没有真正学到 task progress」，跳到下面 B 段。

## 三、B. 训练侧：独立 value-only 模型

### 3.1 为什么要独立模型

V0.1.1 的 value 跟视频生成共用同一个 DiT、同一套 attention、同一个 denoise 过程。**问题**：

- attention 资源被视频生成抢占（5 video latent + 1 value latent → value 只占 1/6 attention "带宽"）
- denoise 过程是为视频设计的（35 步、特定 sigma schedule）；value 是常数 broadcast 标量，可能根本不需要这么复杂
- value 头无法独立优化，无法换更强的 vision encoder / 加 proprio / 调 loss weight

翔哥说"多训一个 predict value 的模型" = **独立 value-only 网络**，把 V(s_t) 当一个**纯回归问题**单独训。

### 3.2 设计草图（备选三档）

| 档 | 网络 | 训练目标 | 数据 | 工程量 |
|---|---|---|---|---|
| **B1. 纯 vision regressor** | DINOv2 / SigLIP backbone + MLP head，输入单帧 image | MSE(V_pred, returns_seq[t]) | 现有 v2 demo + 失败 rollout | 小（~1-2 天）|
| **B2. + proprio** | B1 + 14D state concat 进 MLP | 同上 | 同上 | 小（多加几行）|
| **B3. + action context** | B2 + action[t:t+H] 编码（小 transformer） | 同上 | 同上 | 中（~3 天）|

**推荐 B2**：工程量小，比 B1 多了机器人本体状态信息。如果 B2 判别力不够，再加 action context 升 B3。**不要直接做 B3**，先看 B2 的 baseline。

### 3.3 监督目标（呼应 comment 3 + 4）

```python
# 训练 sample
{
    "image": video[t],                            # ← 输入帧
    "proprio": state[t],                          # 14D
    "action_chunk": action[t:t+16],               # 仅 B3 用
    "value_target": returns_seq[t],               # ← GT 严格对齐输入帧 t
}

# Loss
loss = MSE(model(image, proprio), returns_seq[t])
```

跟 V0.1.1 的差异：
- 不再 broadcast 到 latent frame，**直接标量回归**（更直接、好调）
- 不混 demo + value sample type，**所有 sample 都带 V 监督**
- 失败数据进训练集：`success=False` → `terminal_reward=0` → returns 全是 -1

### 3.4 训练数据混合

| 数据 | 比例（推荐起点）| terminal_reward |
|---|---:|---:|
| Demo（v2 现有 90+90 train） | 70% | 1.0 |
| 失败 rollout（B1 收的 ~30+30）| 30% | 0.0 |

要保证两类数据都 sample 到，否则纯 demo 训出来还是个常数预测器。30% 是经验初值，看 loss 收敛再调。

### 3.5 评估方式

复用 A 段的 dense eval 脚本，但 model forward 换成新 value-only 模型。判别力指标完全一样。

加一个对照基线：
- **基线 0**：随机预测（V ~ U(-1, 1)）
- **基线 1**：V0.1.1 的 V（耦合视频生成）
- **新模型**：value-only B2 / B3

三者在同一组成功+失败 episode 上比末端 V 差和 KS 统计。

### 3.6 实施分阶段

**Phase B-1 数据**（前置，~2 天）：
- 写 `collect_robotwin_failures.py`，收 30+30 条 failure rollout（pcp / pob 各 30）
- 转成 v2 同 schema，`ann["success"]=False`
- 在 dataset 注册 `robotwin_v2_with_failure` mixture

**Phase B-2 模型**（~2-3 天）：
- 写 `cosmos_predict2/_src/predict2/value/value_regressor.py`：DINOv2 backbone + MLP head
- 写训练 config + 启动脚本 `scripts/train_value_regressor_8gpu.sh`
- 单机 8 卡训 ~50k step（这种小模型应该 1 天内收敛）

**Phase B-3 评估**（~半天）：
- 跑 dense eval 在 4 白名单 + 失败集上
- 出 V_pred vs V_gt 双曲线 + 成功/失败叠图
- 跟 V0.1.1（A 段结果）做横评

### 3.7 Done 条件

- [ ] `robotwin_v2_with_failure` mixture 注册好，60 条失败 rollout 转好
- [ ] B2（vision + proprio）训练收敛，loss 曲线正常
- [ ] B2 dense eval：成功末端 V > +0.7，失败末端 V < -0.3
- [ ] V0.1.1 vs B2 横评，判别力指标 B2 显著好
- [ ] 实验记录文档（暂定 `实验记录/V0.3-value-only-regressor.md`）

## 四、整体路径图

```
Phase A.1 (1-2 天) ── dense_value_eval.py + V0.1.1 ckpt 跑 4 白名单稠密曲线
                  │
                  ├─ 如果 V_pred ≈ V_gt 且单调 → V0.1.1 其实学得不错，
                  │  Phase A.2 加失败轨迹也许就能验证判别力，B 段可缓一缓
                  │
Phase A.2 (~2 天) ── 收失败 rollout（pcp+pob 各 30）+ 重跑 dense eval
                  │
                  ├─ 如果 success vs failure V 显著分开 → V0.1.1 够用，B 段不必做
                  │  如果分不开 / V 全是常数 → 强证据需要 B 段
                  │
Phase B (~5-7 天) ── 独立 value-only 模型（B2: vision + proprio）
                  │
                  └─ B2 横评 vs V0.1.1，定哪个上线
```

**先 A 后 B**，不要并行起 B 训练——A 跑完才能判断 B 真的有必要。
