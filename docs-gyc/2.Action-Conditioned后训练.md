## 背景：Cosmos-Predict2.5 的模型体系

Cosmos-Predict2.5 是一个**视频生成模型**，所有变体都在同一个 HuggingFace 仓库 `nvidia/Cosmos-Predict2.5-2B` 中，共享同一个 DiT 2B 架构，但针对不同场景做了不同方向的后训练：

```
nvidia/Cosmos-Predict2.5-2B/
├── tokenizer.pth                        485MB  共用的视频 tokenizer
│
├── base/                                ← 通用视频生成
│   ├── pre-trained/   ............  3.9G  基础预训练（所有模型的起点）
│   ├── post-trained/  ............  3.9G  基础后训练（跑 Image2World 用的）
│   └── distilled/     ............  3.9G  蒸馏模型（4步快速推理）
│
├── auto/                                ← 自动驾驶场景
│   └── multiview/     ............  3.9G  多视角后训练
│
└── robot/                               ← ★ 机器人场景（我们关注的）
    ├── action-cond/   ............  4.0G  Action-Conditioned 世界模型
    ├── multiview-agibot/           4.0G  AgibBot 多视角
    └── policy/
        ├── libero/                 3.9G  策略模型 (LIBERO)
        └── robocasa/               3.9G  策略模型 (RoboCasa)
```

每个 `.pt` 文件都是**完整的独立模型权重**（约 3.9~4.0G，BF16 精度），可直接加载推理。

### 什么是 Action-Conditioned

Action-Conditioned 是一种**条件视频生成**：给模型一张初始画面 + 一串动作指令，模型生成机器人执行这些动作后的视频。

```
输入: 第一帧图片 + 动作序列 [dx,dy,dz,...] × 12帧
输出: 机器人按照这些动作运动的视频
```

训练方法是 **Rectified Flow**（一种扩散模型训练方式）：让网络学习预测从噪声到干净视频的"速度方向"，action 通过 MLP 编码后注入到 DiT 的每一层中，引导生成与动作一致的视频。详见 `docs-gyc/3.Action-Conditioning架构解析.md`。

### robot 目录下 action-cond 和 policy 的区别

这两个是**方向相反**的模型：

| | action-cond（世界模型） | policy（策略模型） |
|---|---|---|
| 做什么 | 给动作，生成视频 | 看视频，输出动作 |
| 输入 | 图片 + 动作序列 | 图片/视频 |
| 输出 | 未来视频 | 动作 + Value |
| 用途 | 模拟"如果这样做，世界会怎样" | 决策"应该怎么做" |
| 类比 | 想象力 | 决策力 |

**我们当前的目标是做 action-cond（世界模型）**，在 RoboTwin 双臂数据上后训练，让模型能根据 14 维双臂动作生成对应的操作视频。

### 为什么我们要做 Action-Conditioned

我们的目标是做**机器人场景的世界模型**：给一张初始画面 + 一串动作指令，模型生成机器人执行这些动作后的视频。这正是 `robot/action-cond` 做的事情。

官方的 `robot/action-cond` 是在 **Bridge 单臂数据集（7 维 action）**上后训练的。我们要做的是在 **RoboTwin 双臂数据集（14 维 action）**上做同样的后训练，让模型支持双臂机器人。

### 模型谱系

```
base/pre-trained                           ← 基础预训练（通用视频生成，720p）
    ↓  加载权重 (strict_resume=False, action MLP 随机初始化)
    ↓  在 Bridge 数据集上后训练 16,000 步 (256×320)
★ robot/action-cond                        ← 官方 action-conditioned 模型（单臂 7 维）
    ↓  我们要做的：加载权重，action_dim 7→14，MLP 输入层重新初始化
    ↓  在 RoboTwin 数据集上后训练
☆ robot/action-cond-robotwin               ← 目标：双臂 14 维
```

| 项目 | 值 |

### Bridge 数据集

Bridge（BridgeData V2）是 UC Berkeley 的**单臂桌面机器人操作数据集**。一个小机器臂（WidowX 250）在桌上做抓取、移动、放置等任务，同时录像并记录每一帧的机器人状态。

**它在这个项目中的角色**：官方用来演示和预训练 Action-Conditioned 能力的示例数据集。

### 数据目录结构

```
assets/action_conditioned/basic/bridge/
├── annotation/test/     ← 标注文件（JSON），记录每帧的机器人状态和动作
│   ├── 0.json           ← episode 0 的标注
│   ├── 1.json           ← episode 1 的标注
│   ├── 3.json
│   ├── 6.json
│   ├── 11.json
│   └── 12.json
└── videos/test/         ← 对应的操作录像
    ├── 0/rgb.mp4        ← episode 0 的视频
    ├── 1/rgb.mp4
    ├── 3/rgb.mp4
    ├── 6/rgb.mp4
    ├── 11/rgb.mp4
    └── 12/rgb.mp4
```

编号（0, 1, 3, 6, 11, 12）是不同的 **episode**（一次完整的任务执行）。编号不连续是因为这只是从完整数据集里抽出来的 6 个测试样本。

### Annotation 标注格式

每个 JSON 是一个 episode 的完整记录。以 `0.json` 为例：

```json
{
  "texts": ["move the spatula to the far left corner behind the pot"],
  "videos": [{"video_path": "videos/test/0/rgb.mp4"}],
  "state": [
    [0.295, -0.003, 0.138, -3.113, -0.138, -0.032, 1.0],
    [0.296, -0.003, 0.138, -3.111, -0.138, -0.033, 1.0],
    ...
  ],
  "continuous_gripper_state": [0.0005, 0.0005, ...],
  "action": [
    [0.0, -0.0002, -0.0, 0.0014, 0.0, 0.0006, 1.0],
    ...
  ],
  "episode_id": "0"
}
```

| 字段 | 形状 | 说明 |
|------|------|------|
| `texts` | 列表 | 任务的自然语言描述 |
| `videos` | 列表 | 对应视频的路径 |
| `state` | [28帧, 7维] | 每帧机器臂的**绝对位姿** `[x, y, z, roll, pitch, yaw, gripper]` |
| `continuous_gripper_state` | [28帧] | 每帧夹爪开合度（0=开，1=闭） |
| `action` | [27帧, 7维] | 帧间**位移增量** `[dx, dy, dz, droll, dpitch, dyaw, gripper_cmd]`（比 state 少一帧） |
| `episode_id` | 字符串 | episode 编号 |

**video** 是机器人操作的录像，**annotation** 是同步记录的数值数据。两者一一对应。

### Action 维度定义（7 维，单臂）

```
action = [dx, dy, dz, droll, dpitch, dyaw, gripper]
          ├────────┤  ├──────────────────┤  ├──────┤
          位置增量(3)    姿态增量-欧拉角(3)   夹爪(1)
```

- **位置增量** `[dx, dy, dz]`：在上一帧坐标系下的平移（毫米级，很小的值）
- **姿态增量** `[droll, dpitch, dyaw]`：相对旋转的欧拉角
- **夹爪** `gripper`：0=打开，1=关闭

注意：annotation 中的 `action` 字段是原始增量，训练/推理时代码会从 `state` 重新计算相对变换并乘以缩放系数（×20），详见架构解析文档。

### 推理做了什么

一句话：**给第一帧图片 + 一串动作指令，模型"想象"出机器人执行这些动作后的视频**。

```
输入：                              输出：
┌──────────┐  ┌──────────────┐     ┌──────────────────────────────────┐
│ 第1帧图片 │ + │ 12帧动作序列  │ →  │ 生成的13帧视频（1帧条件+12帧生成）│
│ (真实)    │  │ [dx,dy,dz...]│     │ 画面展示机器人按指令移动的样子    │
└──────────┘  └──────────────┘     └──────────────────────────────────┘
```

对于超过 12 帧的长轨迹，模型**自回归**生成：
1. 取第 1 帧 + 前 12 帧 action → 生成 chunk 1
2. 取 chunk 1 最后一帧 + 接下来 12 帧 action → 生成 chunk 2
3. 依此类推，拼接所有 chunk 得到完整视频

### 推理参数

配置文件 `assets/action_conditioned/basic/inference_params.json`：

```json
{
  "name": "basic",
  "input_root": "assets/action_conditioned/basic/bridge",
  "input_json_sub_folder": "annotation/test",
  "save_root": "outputs/action_conditioned/basic",
  "guidance": 0,
  "resolution": "256,320",
  "camera_id": 0,
  "chunk_size": 12,
  "num_latent_conditional_frames": 1,
  "action_scaler": 20.0,
  "use_quat": false,
  "seed": 0
}
```

| 参数 | 值 | 说明 |
|------|-----|------|
| `chunk_size` | 12 | 每次生成 12 帧 |
| `resolution` | 256×320 | 输出分辨率 |
| `guidance` | 0 | 无分类器引导 |
| `num_latent_conditional_frames` | 1 | 1 帧条件帧 |
| `action_scaler` | 20.0 | action 缩放系数 |

推理使用的是 `robot/action-cond` 模型（详见文档开头的模型体系说明）。
