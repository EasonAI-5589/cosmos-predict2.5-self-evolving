# 20. Value 头依赖 Action 的实证 — 需要重训纯视觉 V

> 关键结论：V0.1.1 的 value 头实际上是 `V(image, action)` 联合函数。把 action 抹零，V 几乎打不出有意义的分。要拿一个"只看图就给 progress"的 V，必须重训。
>
> 前置阅读：`18. Value评估-当前闭环实现.md`、`19. Value优化-按翔哥Comment重设计.md`、`实验记录/V0.1.1-16f-with-value.md` 的"开环零动作评估"小节。

---

## 一、一句话

V0.1.1 训练的 value 头是 V(image, action_chunk)——**图和动作一起决定 V**，不是只看图。所以拿这个 ckpt 单纯喂 image（action 置零）想拿到 dense progress 信号，**做不到**。

---

## 二、实证（zero-action 开环测试）

把 V0.1.1 ckpt 不动，推理时把 action_chunk 全设 0，喂同一张 cond 帧，对比"GT action"和"zero action"两种输入下 V 曲线：

| 实验 | V0 | V_-1 | range | shape |
|---|---:|---:|---:|---|
| pcp_0091 success **GT-action** | -0.589 | +0.687 | 1.28 | 平滑斜坡（学到的样子）|
| pcp_0091 success **zero-action** | -0.250 | +0.277 | 0.54 | 前 70% 平到底，末段才阶跃 |
| pcp_fail10 failure **zero-action** | -0.287 | -0.273 | **0.04** | 全程死平 |

**含义**：
- 把 action 从 GT 换成 0，**同一条 episode** range 从 1.28 缩到 0.54——~60% 的 V 信号靠 action 提供
- 视觉信号确实存在，但**只在末段 ~25% 才"开火"**（zero-action 时前 70% V 不动，末端才跳）
- 失败视频 zero-action 全程平在 -0.28，证明视觉确实能区分 success/failure，但只在末态识别那一下

产物：`outputs/zero_action_eval_v01_1/stack_3way_action_ablation.mp4`（左视频 + 右 V 曲线，三行垂直叠对比）

同一条 success episode 直接对照 GT-action vs zero-action，再加一条 failure 用 zero-action 看末态判别：

肉眼能直接看到的三个关键现象：

- **GT-action 是平滑斜坡**：pcp_0091 GT 的 V 从 -0.59 一路爬到 +0.69（range 1.28）——这是"模型学到的 progress 信号该长这样"

## 三、为什么 V0.1.1 训出来是这样的

去看代码 `cosmos_predict2/_src/predict2/action/networks/action_conditioned_minimal_v1_lvg_dit.py:269-286`：

- 输入是 6 个 latent 帧：1 cond image + 4 future video + 1 value
- DiT 是 self-attention 跨这 6 帧的
- action_emb 直接加到前 5 帧的 timestep / adaLN modulation；**value 帧那一路已经 pad 0 了**
- 但 value 帧通过 attention 还能"看到"前 5 帧——action 信息**间接漏过来**

训练时模型 fit `returns_seq[fids[0]]` 这条平滑曲线，发现：
- 16 步 action chunk 在不同 t 长得很不一样 → **action 路径**能轻松编码 episode 位置
- 单帧 image 在前 70% 看起来都很像 → **视觉路径**只能学末端识别

模型自然分工：action 管全程 progress，vision 管末态识别。两者加起来拟合 returns。

## 四、想要"V 只看图就能打分"，怎么办

V0.1.1 这个 ckpt 直接用是不行的。三档改法（doc 19 同步详细方案）：

| 方案 | 干啥 | 工程量 |
|---|---|---|
| **A. action dropout 续训** | 训练时 50% 概率把 action 置零，逼模型有时只能用图 | 改 5 行，续训 V0.1.1 ~20-30k step |
| **B. attention masking 续训** | DiT 里禁止 value 帧 attend 到被 action 调制的 4 个视频帧 | ~半天 |
| **C. 重训独立 V(s) 网络** | 单独的小模型（DINOv2+MLP），输入只 image，跟视频生成完全解耦 | 5-7 天 + 必须有失败 rollout |

**关键约束**：A/B/C 任何一种，**只用 demo 数据训不出真正的纯视觉 V**——demo 里所有帧 returns 都是从 -1 平滑升到 +1，模型只会学一个"看图判断 episode 位置"的回归器。要让模型知道"什么是失败画面 → V 该是 -1"，必须**混入失败 rollout**（terminal_reward=0 → returns 整条 -1）。

---

## 五、建议路径

1. **先做 A**（最便宜）：续训 V0.1.1，加 `action_dropout_prob=0.5`，跑 20-30k step
2. 用现成的 `scripts/workflow/value_open_loop.py --zero-action` 重测，看 zero-action 时 V 曲线是否变平滑
3. 如果 A 出效果 → 大概率不需要 B/C，拿这个续训版 ckpt 当"image-only V"用就行
4. 如果 A 没效果 → 大概率是 demo-only 训不出来，去 doc 19 B 段 + 收失败 rollout，搭配 C
5. 失败 rollout 数据来源：`/mnt/gyc_ckp/RoboTwin/eval_result/{task}/.../fail_episode*.mp4`（pcp 3404 + pob 4918 条），但**没存对应 state/action**——B 段如果做需要单独工程：要么从视频 IK 反推，要么重跑 RoboTwin sim 同时 dump trajectory
