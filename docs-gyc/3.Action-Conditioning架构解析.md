# 3. Action Conditioning 架构解析

本文档深入分析 Cosmos-Predict2.5 中 Action Conditioning 的实现原理，帮助理解 action 如何作为条件注入视频生成模型。

---

## 一、总览

Action Conditioning 的核心思想：**将机器人动作序列编码为 embedding，注入到 DiT（Diffusion Transformer）的去噪过程中**，使生成的视频与给定的动作轨迹一致。

```
                    训练/推理数据流
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  输入数据                                                 │
│  ├── 视频帧 (条件帧)                                      │
│  ├── 文本描述 (prompt)                                    │
│  └── 动作序列 action [T, action_dim]   ← 核心新增条件      │
│                                                          │
│       ↓                                                  │
│  ┌─────────────┐                                         │
│  │ Conditioner │  提取各类条件信息                          │
│  │             │  action 直接透传，不做变换                  │
│  └──────┬──────┘                                         │
│         ↓                                                │
│  ┌─────────────────────────────────┐                     │
│  │ DiT Network (2B/7B/14B)        │                      │
│  │                                 │                     │
│  │  action → MLP → action_emb     │                     │
│  │                  ↓              │                     │
│  │  timestep_emb += action_emb    │  ← 注入方式          │
│  │  adaln_lora   += action_emb    │                     │
│  │                  ↓              │                     │
│  │  DiT Blocks (28层)              │                     │
│  │                  ↓              │                     │
│  │  输出: 预测的速度场/噪声          │                     │
│  └─────────────────────────────────┘                     │
│         ↓                                                │
│  去噪 → 解码 → 生成视频                                    │
└──────────────────────────────────────────────────────────┘
```

---

## 二、Action 的表示

### 2.1 单臂 7 维（Bridge 数据集，官方默认）

每一帧的 action 是一个 7 维向量，表示**相对于上一帧的增量**：

```
action = [dx, dy, dz, droll, dpitch, dyaw, gripper]
          ├────────┤  ├──────────────────┤  ├──────┤
          位置增量(3)    姿态增量-欧拉角(3)   夹爪(1)
```

- **位置增量** `[dx, dy, dz]`：在上一帧坐标系下的平移
- **姿态增量** `[droll, dpitch, dyaw]`：相对旋转的欧拉角表示
- **夹爪** `gripper`：0=打开，1=关闭

### 2.2 动作计算方式

动作不是直接从数据中读取，而是**从连续帧的 state 中计算出来的相对变换**：

```python
# dataset_local.py:_get_actions() (训练) 和 action_conditioned.py:_get_actions() (推理)
# 相同的计算逻辑：

for k in range(1, sequence_length):
    prev_xyz = arm_states[k-1, 0:3]
    prev_rotm = euler2rotm(arm_states[k-1, 3:6])  # 上一帧的旋转矩阵
    curr_xyz = arm_states[k, 0:3]
    curr_rotm = euler2rotm(arm_states[k, 3:6])

    # 相对平移（在上一帧坐标系下）
    rel_xyz = prev_rotm.T @ (curr_xyz - prev_xyz)
    # 相对旋转
    rel_rotm = prev_rotm.T @ curr_rotm
    rel_rpy = rotm2euler(rel_rotm)

    action[k-1, 0:3] = rel_xyz
    action[k-1, 3:6] = rel_rpy
    action[k-1, 6] = curr_gripper
```

### 2.3 动作缩放 (Action Scaling)

计算出的 action 值很小（毫米级位移），需要乘以缩放系数才能有效作为网络输入：

```python
# 缩放系数（默认值）
c_act_scaler = [20.0, 20.0, 20.0, 20.0, 20.0, 20.0, gripper_rescale_factor]
#               ├── 位置 ×20 ──┤  ├── 姿态 ×20 ──┤   gripper ×1

actions *= c_act_scaler  # 逐维度缩放
```

        self.action_dim = 7                          # ← 硬编码 7 维
        self.c_act_scaler = [20.0]*6 + [gripper_rescale_factor]  # ← 硬编码 7 个值

#### Step 2: Conditioner 提取条件

**文件**: `cosmos_predict2/_src/predict2/action/configs/action_conditioned/conditioner.py`

```python
# Action 条件数据类 — 继承自 Video2WorldCondition
@dataclass(frozen=True)
class ActionConditionedCondition(Video2WorldCondition):
    action: Optional[torch.Tensor] = None  # ← 新增 action 字段

# Action 条件提取器
class ActionConditionedConditioner(Video2WorldConditioner):
    def forward(self, batch, ...):
        output = super()._forward(batch, ...)     # 处理 text, video, fps 等
        output["action"] = batch["action"]         # ← 直接透传 action tensor
        return ActionConditionedCondition(**output)
```

**关键点**：Conditioner 对 action **不做任何变换**，只是从 batch 中取出并打包到 condition 对象中。action 的维度在这里完全透明。

#### Step 4: Network 处理 action（核心）

**文件**: `cosmos_predict2/_src/predict2/action/networks/action_conditioned_minimal_v1_lvg_dit.py`

官方训练使用的是 `ActionChunkConditionedMinimalV1LVGDiT`（Chunk 版本），它按时间压缩比对 action 分组处理。

```python
class ActionChunkConditionedMinimalV1LVGDiT(MiniTrainDIT):
    def __init__(self, *args, **kwargs):
        action_dim = kwargs.get("action_dim", 80)               # 从 config 读取，默认 80
        self._num_action_per_latent_frame = kwargs.get(
            "temporal_compression_ratio", 4)                      # 时间压缩比，默认 4

        # ★ 两个 MLP 将 action 编码为 embedding
        # 输入维度 = action_dim × 每个 latent frame 对应的 action 数
        # 例如: 7 × 4 = 28
        self.action_embedder_B_D = Mlp(
            in_features=action_dim * self._num_action_per_latent_frame,  # 28
            hidden_features=self.model_channels * 4,                     # 2048×4 = 8192
            out_features=self.model_channels,                            # 2048
        )
        self.action_embedder_B_3D = Mlp(
            in_features=action_dim * self._num_action_per_latent_frame,  # 28
            hidden_features=self.model_channels * 4,                     # 8192
            out_features=self.model_channels * 3,                        # 6144 (用于 AdaLN)
        )

    def forward(self, ..., action=None, ...):
        # ★ Step 4a: 将 action reshape 为 per-latent-frame 的分组
        num_actions = action.shape[1]  # 如 12
        action = rearrange(action, "b t d -> b 1 (t d)")
        # 按时间压缩比分组: [B, 1, 12×7] → [B, 3, 4×7]
        # 每个 latent frame 对应 4 个原始帧的 action
        action = rearrange(action, "b 1 (t d) -> b t d",
                          t=num_actions // self._num_action_per_latent_frame)

        # ★ Step 4b: MLP 编码
        action_emb_B_D = self.action_embedder_B_D(action)    # [B, 3, 2048]
        action_emb_B_3D = self.action_embedder_B_3D(action)  # [B, 3, 6144]

        # ★ Step 4c: 给条件帧的 action 补零（第一帧是条件帧，不需要 action）
        zero_pad = torch.zeros_like(action_emb_B_D[:, :1, :])
        action_emb_B_D = torch.cat([zero_pad, action_emb_B_D], dim=1)    # [B, 4, 2048]
        action_emb_B_3D = torch.cat([zero_pad, action_emb_B_3D], dim=1)  # [B, 4, 6144]

        # ★ Step 4d: 用条件帧 mask 屏蔽条件帧的 action（只影响需要生成的帧）
        condition_mask = (1 - condition_video_input_mask[:, 0, :, 0, 0]).unsqueeze(-1)
        action_emb_B_D = action_emb_B_D * condition_mask
        action_emb_B_3D = action_emb_B_3D * condition_mask

        # ★ Step 4e: 注入到 timestep embedding（核心注入方式）
        t_embedding, adaln_lora = self.t_embedder(timesteps)
        t_embedding = t_embedding + action_emb_B_D    # ← action 加到 timestep embedding
        adaln_lora = adaln_lora + action_emb_B_3D     # ← action 加到 AdaLN
        t_embedding = self.t_embedding_norm(t_embedding)

        # ★ Step 4f: 正常执行 DiT blocks
        for block in self.blocks:
            x = block(x, t_embedding, crossattn, adaln_lora=adaln_lora, ...)

        return self.unpatchify(self.final_layer(x, t_embedding, adaln_lora=adaln_lora))
```

## 四、Action 注入机制详解

### 4.1 为什么加到 timestep embedding？

在 DiT 中，timestep embedding 通过 **AdaLN (Adaptive Layer Normalization)** 控制每一层的 scale 和 shift。将 action embedding 加到 timestep embedding 上，等价于**让 action 条件通过 AdaLN 全局调制每一层的特征**。

```
                    ┌───────────────┐
                    │  Timestep t   │
                    └──────┬────────┘
                           │
                    ┌──────▼────────┐
                    │ t_embedder    │ → t_emb [B, T_latent, D], adaln [B, T_latent, 3D]
                    └──────┬────────┘
                           │
               ┌───────────▼───────────┐
               │  t_emb += action_emb  │  ← Action 注入点
               │  adaln += action_emb  │
               └───────────┬───────────┘
                           │
                    ┌──────▼────────┐
                    │  LayerNorm    │ → 归一化
                    └──────┬────────┘
                           │
                    ┌──────▼────────┐
                    │  DiT Block ×28│ → 每层通过 AdaLN 接收 action 信息
                    │               │
                    │  AdaLN:       │
                    │  scale = f(t_emb + action_emb)
                    │  shift = g(t_emb + action_emb)
                    │  x = scale * LayerNorm(x) + shift
                    └──────┬────────┘
                           │
                    ┌──────▼────────┐
                    │  Final Layer  │ → 同样通过 AdaLN 接收 action 信息
                    └───────────────┘
```

### 4.2 Chunk 版本的 action embedding（官方训练使用）

`ActionChunkConditionedMinimalV1LVGDiT` 的关键改进是 **按 latent frame 分组处理 action**：

由于视频有时间压缩（`temporal_compression_ratio=4`，即 4 个原始帧压缩成 1 个 latent frame），所以 12 帧 action 对应 3 个 latent frame。每个 latent frame 有独立的 action embedding：

```
原始 action: [a1, a2, a3, a4, a5, a6, a7, a8, a9, a10, a11, a12]  (每个 ai 是 7 维)
                ↓ 按时间压缩比 4 分组
Latent frame 1: [a1, a2, a3, a4]   → flatten → MLP → emb_1 [D]
Latent frame 2: [a5, a6, a7, a8]   → flatten → MLP → emb_2 [D]
Latent frame 3: [a9, a10, a11, a12] → flatten → MLP → emb_3 [D]
                ↓ 补零（条件帧）
最终 action_emb: [0, emb_1, emb_2, emb_3]  shape: [B, 4, D]
```

- `state_t = 1 + 12 // 4 = 4`（1 个条件 latent frame + 3 个生成 latent frame）
- 每个 latent frame 的 MLP 输入维度 = `action_dim × temporal_compression_ratio = 7 × 4 = 28`

### 4.3 两种 Network 变体对比

| 特性 | `ActionConditionedMinimalV1LVGDiT` | `ActionChunkConditionedMinimalV1LVGDiT` |
|------|----|----|
| MLP 输入 | `action_dim × num_action_per_chunk` (如 7×12=84) | `action_dim × temporal_compression_ratio` (如 7×4=28) |
| Action 分组 | 所有 action flatten 为一个向量 | 按 latent frame 分组 |
| Embedding 维度 | `[B, 1, D]` 全局一个 | `[B, T_latent, D]` 每帧一个 |
| 条件帧处理 | 无 | 给条件帧补零 + mask |
| 官方使用 | 旧版本 | **当前官方训练使用** |
| Config 中的名称 | `cosmos_v1_2B_action_conditioned` | `cosmos_v1_2B_action_chunk_conditioned` |

## 六、双臂扩展分析（预备知识）

### 6.1 需要修改的文件

| 文件 | 修改内容 | 影响 |
|------|---------|------|
| **Config** | `action_dim=7` → `14` | 自动改变 MLP 输入维度 |
| **Dataset** `dataset_local.py` | 新建子类处理双臂 state/action | 数据加载 |
| **Inference** `action_conditioned.py` | `_get_actions` 支持双臂 | 推理时的 action 处理 |

### 6.2 不需要修改的文件

| 文件 | 原因 |
|------|------|
| **Network** `action_conditioned_minimal_v1_lvg_dit.py` | `action_dim` 完全参数化 |
| **Conditioner** `conditioner.py` | 只透传 tensor，对维度无感知 |
| **Model** `action_conditioned_video2world_rectified_flow_model.py` | 通过 `condition.to_dict()` 透传 |
| **Inference handler** `video2world.py` | `data_batch["action"]` 直接传递 |

### 6.3 MLP 维度变化

将 `action_dim` 从 7 改为 14 后：
- MLP 输入维度：`14 × 4 = 56`（原来 28）
- MLP 隐藏维度：不变 `8192`
- MLP 输出维度：不变 `2048` / `6144`
- **新增的 MLP 参数会随机初始化**（`strict_resume=False` 保证加载不报错）
