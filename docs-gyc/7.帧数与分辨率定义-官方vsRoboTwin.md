# 7. 帧数与分辨率定义 — 官方 vs RoboTwin

## 背景简介

Cosmos-Predict2.5 官方给的 Action-Conditioned 后训练**示例是基于 Bridge 数据集**（单臂机器人，action 是 7 维末端执行器位姿 + 夹爪），在 256×320 分辨率、13 帧（1 条件 + 12 生成）的设定下训练。

**我们要做的**是把这套流程迁移到 **RoboTwin 双臂仿真数据**上：
- **数据来源**：RoboTwin 仿真环境渲染的两个任务 —— `place_container_plate`（pcp）和 `place_object_basket`（pob）
- **规模**：每个任务 100 episode，两个任务合计 200 episode，按 9:1 划分为 **180 train / 20 val**
- **动作空间**：**14 维双臂** = 左臂 7 维 + 右臂 7 维（每臂 = xyz + 欧拉角 + gripper）
- **原始视频**：RoboTwin 以 30 FPS 渲染（Bridge 约 4 FPS，差 ≈8×）
- **预训练起点**：直接加载官方 `robot/action-cond` 的后训练权重 `38c6c645-..._ema_bf16.pt`，只让 action MLP 的输入层因 7→14 维变化而重新初始化

**核心目标**：帧数、分辨率等关键超参尽量跟官方对齐，以便沿用官方预训练权重、复用经过验证的配置，并在训练稳定后能直接和官方 Bridge 的结果做 sanity check。唯一必须改动的是 `action_dim`（7→14）和 `fps_downsample_ratio`（1→10，把 30 FPS 下采到 ≈3 FPS 匹配 Bridge 的时序密度）。

---

> 回答翔哥的两个问题：
> 1. 官方 Action-Conditioned 后训练任务是如何定义帧数、分辨率的？
> 2. 我们的 RoboTwin 后训练是怎么定义的？

## 一、核心结论（一行表格）

| 维度 | 官方 Bridge | 我们 RoboTwin |
|------|------------|--------------|
| **生成帧数** | 13 帧 = 1 条件帧 + 12 生成帧 | **13 帧（完全对齐）** |
| **num_action_per_chunk** | 12 | **12（对齐）** |
| **latent 时间长度 state_t** | 1 + 12/4 = 4 | **4（对齐）** |
| **训练分辨率** | 256 × 320 | **256 × 320（对齐）** |
| **Dataset 默认分辨率** | 480 × 640（被 experiment 覆盖为 256×320） | 直接 256 × 320 |
| **FPS 采样** | fps_downsample_ratio = 1（原始 ≈4 FPS 直用） | fps_downsample_ratio = **10**（30→3 FPS，匹配 Bridge 时序密度） |
| **Action 维度** | 7（单臂） | **14（双臂）** |
| **相机数** | cam_ids=[0] | cam_ids=[0] |

**一句话总结**：帧数、分辨率、chunk 大小完全跟官方一致，只在 `action_dim`（7→14）和 `fps_downsample_ratio`（1→10）上做了必要改动。

## 二、官方是怎么定义的

官方把帧数/分辨率分两层定义：**数据层** + **实验层覆盖**。

### 2.1 数据层（dataset 本体）

文件：`cosmos_predict2/_src/predict2/action/configs/action_conditioned/data.py`

```python
bridge_13frame_480_640_train_dataset = L(Dataset_3D)(
    ...
    fps_downsample_ratio=1,
    num_action_per_chunk=12,      # ← 每个 chunk 12 帧 action
    cam_ids=[0],
    video_size=[480, 640],        # ← dataset 层默认 480×640
    mode="train",
)
```

注册到 Hydra：`data_train=bridge_13frame_480_640_train`。

### 2.2 实验层覆盖（真正用来训练的值）

文件：`cosmos_predict2/experiments/base/action.py`
实验名：`ac_reason_embeddings_rectified_flow_2b_256_320`

```python
model=dict(config=dict(
    min_num_conditional_frames=1,
    max_num_conditional_frames=1,
    state_t = 1 + 12 // 4,         # ← latent 时间 = 4 帧
    net=dict(
        action_dim=7,              # ← 单臂 7 维
        temporal_compression_ratio=4,
    ),
)),
dataloader_train=dict(
    batch_size=8,
    dataset=dict(
        num_action_per_chunk=12,   # ← 再确认一次
        fps_downsample_ratio=1,
        video_size=[256, 320],     # ★ 实验层覆盖为 256×320（不再是 480×640）
    ),
),
```

### 2.3 帧数推导

```
sequence_length = 1 + num_action_per_chunk = 1 + 12 = 13 帧
  ├── 第 1 帧：条件帧（用户给的起始图像）
  └── 第 2~13 帧：模型要生成的 12 帧

latent_time = 1 + num_action_per_chunk / temporal_compression_ratio
            = 1 + 12/4 = 4 个 latent frame
```

VAE 时间压缩比 4，所以 12 个原始帧被压成 3 个 latent frame，再加 1 个条件 latent frame = `state_t = 4`。

### 2.4 为什么数据层是 480×640、实验层又覆盖成 256×320？

- **历史原因**：官方保留了 480×640 的原始 dataset 配置，便于切换到高分实验。
- **实际训练**：2B 模型默认用 256×320 训（即 `_2b_256_320` 后缀），显存/速度都更友好。
- 实验层的 override 会压倒 dataset 层的默认值，所以真正进入模型的是 256×320。

## 三、RoboTwin 是怎么定义的

我们在**同一套机制**下新增了 RoboTwin 的配置，做法是：数据层直接写成最终值（256×320），实验层继承官方并 override 数据集。

### 3.1 数据层

文件：`cosmos_predict2/_src/predict2/action/configs/action_conditioned/data.py`

```python
robotwin_base_path = "/mnt/gyc_ckp/cosmos-predict2.5-robotwin"

robotwin_13frame_train_dataset = L(Dataset_3D)(
    train_annotation_path=robotwin_train_annotation_path,
    val_annotation_path=robotwin_val_annotation_path,
    video_path=robotwin_base_path,
    fps_downsample_ratio=10,      # ★ RoboTwin 原始 30 FPS → 每 10 帧取 1 帧 ≈ 3 FPS
    num_action_per_chunk=12,      # ← 对齐官方
    cam_ids=[0],
    video_size=[256, 320],        # ★ 直接定为训练尺寸，不再有 480×640
    mode="train",
    action_dim=14,                # ★ 双臂 14 维（7+7）
)
```

注册名：`robotwin_13frame_train` / `robotwin_13frame_val`。

### 3.2 实验层

文件：`cosmos_predict2/_src/predict2/action/configs/action_conditioned/experiment/exp_2B_action_conditioned_rectify_flow.py`
实验名：`cosmos_predict2p5_2B_action_conditioned_rectified_flow_robotwin_14d_13frame_256x320`

```python
AC_ROBOTWIN_14D_RECTIFIED_FLOW_2B = LazyDict(dict(
    defaults=[
        "/experiment/cosmos_predict2p5_2B_reason_embeddings_action_conditioned_rectified_flow_bridge_13frame_480_640_",
        {"override /net": "cosmos_v1_2B_action_chunk_conditioned"},
        {"override /data_train": "robotwin_13frame_train"},   # ← 换成 RoboTwin 数据
        {"override /data_val":   "robotwin_13frame_val"},
        {"override /checkpoint": "local"},
    ],
    checkpoint=dict(
        load_path="/mnt/gyc_ckp/models/Cosmos-Predict2.5-2B/robot/action-cond/38c6c645-...ema_bf16.pt",
        strict_resume=False,       # ← action MLP 输入维度从 7→14 变了，必须非严格加载
    ),
    model=dict(config=dict(
        state_t = 1 + 12 // 4,     # ← 4，对齐官方
        net=dict(
            action_dim=14,         # ★ 7 → 14
            num_action_per_chunk=12,
            temporal_compression_ratio=4,
        ),
    )),
    dataloader_train=dict(
        batch_size=2,              # ← 单卡显存限制，官方是 8
        dataset=dict(
            gripper_rescale_factor=1,
            num_action_per_chunk=12,       # ← 对齐
            fps_downsample_ratio=10,       # ← RoboTwin 专属
            video_size=[256, 320],         # ← 对齐（冗余 override 保险）
        ),
    ),
))
```

### 3.3 与官方的差异点（只列不一样的）

| 项 | 官方 | RoboTwin | 原因 |
|---|---|---|---|
| `video_size` 在哪定义 | dataset=480×640，experiment 覆盖成 256×320 | dataset 直接 256×320 | 省一层覆盖，语义更明确 |
| `fps_downsample_ratio` | 1 | **10** | RoboTwin 是 30 FPS 高帧率仿真，需下采样到 ≈3 FPS 才能匹配 Bridge 的时序密度（否则 13 帧只覆盖 0.4 秒） |
| `action_dim` | 7 | **14** | 双臂 = 左臂 7 + 右臂 7 |
| `batch_size` | 8 | 2（单卡）/ 16（8 卡） | 显存 |
| `load_path` | S3 预训练 | 本地 `robot/action-cond/..._ema_bf16.pt` | 从官方 action-cond 后训练 ckpt 起步（MLP 输入层会因 7→14 重新初始化） |
| `strict_resume` | 默认 | **False** | 必须——action MLP 维度变了 |

---

## 四、为什么选择严格对齐 13 帧 / 256×320

- **显存**：256×320 + 13 帧 在 2B 模型下单卡刚好能塞下 batch=2；动一点都容易 OOM。
- **预训练权重**：直接加载官方 `robot/action-cond` 的 ema_bf16.pt，DiT 的空间/时间位置编码都是按 256×320 × 13 帧学的，尺寸一变就要重新适配，失去从后训练 ckpt 起步的优势。
- **验证一致性**：等跑通后要跟官方 Bridge 的结果做 sanity check，完全对齐帧数和分辨率时才能直接比较 loss 曲线。

唯一不得不改的是 **FPS 采样**（`fps_downsample_ratio=10`），因为 RoboTwin 是 30 FPS 渲染的仿真数据，如果直接用，13 帧只对应 0.43 秒，动作幅度太小根本学不到有效信号；下采样到 3 FPS 后，13 帧覆盖 ≈4.3 秒，和 Bridge 数据的时序跨度基本一致。
