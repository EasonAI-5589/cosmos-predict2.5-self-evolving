# V0.1 —— 224×224 多 seed 消融（推翻"224 必崩"结论）

V0.1 (seed=0) 当初跑满 100k 后 iter 50k+ 出现纯噪声视频，让我们误以为 224×224 架构本身有问题。这组实验**同配置换 seed 重跑 30k**，发现 seed5 完全正常收敛、视频能完整完成抓取+放置，**证明崩坏是 seed 特定现象，不是分辨率元凶**。

跟 V0.1 (seed=0) 唯一差别：
- `trainer.seed`: 0 → 1-100 共 8 个 seed
- 训练步数：100k → **30k**（节省算力，够看趋势）
- 数据：已经是 v2 default
- 其他所有参数完全继承 V0.1（224×224, chunk=16, state_t=5, fps_downsample_ratio=1）

## 实验目的

V0.1 (seed=0) 的"iter 50k+ 视觉崩坏"观察让我们误判了 224×224 分辨率。在 V0.1.2 (256×256) / V0.1.3 (256×320) 验证 256+ 可以工作后，需要回答：

> **同样 224×224 配置，换 seed 还会崩吗？还是 seed=0 个例？**

## 启动脚本

## 结论

### 1. 224×224 不是崩坏元凶

seed5 在 224×224 同配置下 iter 10k → 30k **指标单调上升，视频完整执行动作**，彻底推翻 V0.1 (seed=0) 的"224 必崩"观察。

### 2. seed 方差的影响大于分辨率

同架构下 final loss 从 **0.0194 (seed5) → 0.0492 (seed100)** 差 2.5×，说明"是否收敛"很大程度依赖 seed；说明当前配置训练稳定性还有提升空间。

### 3. seed5 @ 224×224 超过了 V0.1.3 @ 256×320

| 实验 | 分辨率 | iter | PSNR | LPIPS |
|---|---|---|---|---|
| V0.1 seed0 | 224×224 | 10k | 17.66 | 0.28 |
| V0.1.2 | 256×256 | 10k | 17.85 | 0.17 |
| V0.1.3 | 256×320 | 10k | 19.42 | 0.18 |
| **seed5** | **224×224** | **10k** | **21.25** | **0.12** |
| **seed5** | **224×224** | **30k** | **22.51** | **0.10** |

**启示**：分辨率不是最大收益来源，**seed + 训练稳定性** 收益更大。后续做 Qosmos 双刀流等实验时，**跑 3 个 seed 选最好的**可能比升分辨率更划算。
