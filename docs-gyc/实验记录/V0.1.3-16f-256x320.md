# V0.1.3 —— 16 帧 + 256×320（老 baseline aspect）

V0.1 + 改分辨率到 **256×320**（跟老 14D baseline aspect 一致）+ 数据切到 **v2**。**单变量分辨率消融实验**，验证 V0.1 的 224×224 是否是导致 50k+ 视觉崩坏的因素之一。

跟 V0.1 的差别：
- `video_size`: [224, 224] → **[256, 320]**
- 数据：v1 → **v2**（pcp 90/10 + pob 90/10 均衡切分）
- `data["fps"]` 训练 tag: 4 → **24**（`dataset_local.py:435` 已统一改，三组分辨率实验共享）

其他全继承 V0.1：`fps_downsample_ratio=1`, `chunk=16`, `state_t=5`。

## 实验目的

跟 V0.1.2 配套，三组分辨率消融：

- **V0.1.2 (256×256)**：方形，token 1024
- **V0.1.3 (256×320)**：老 baseline aspect，token **1280**
- **V0.1 (224×224)**：当前已知崩坏，token 784

V0.1.3 是最接近老 14D baseline（256×320 + 13 帧 + ratio=10）的分辨率配置，跟 V0.1 的唯一差别就是分辨率。如果 V0.1.3 不崩、V0.1 崩，那分辨率是核心元凶；如果两个都崩，则锁定到 `fps_downsample_ratio=1` 是元凶（这是跟 baseline 的另一个关键差异）。

## 结论

跟 V0.1.2 比较验证**分辨率 ≥ 256 是关键**：

| 维度 | V0.1.2 (256×256) | V0.1.3 (256×320) |
|---|---|---|
| Final loss | **0.0608** | 0.0932 |
| iter 4k pob_0091 PSNR | 16.50 | **19.01** |
| iter 4k pob_0091 SSIM | **0.86** | 0.77 |
| iter 4k pob_0091 LPIPS | **0.18** | 0.32 |

V0.1.3 PSNR 高（pixel 级更准），V0.1.2 SSIM/LPIPS 低（结构/感知更像）。两者都大幅优于 V0.1 (224×224)——**元凶锁定到 224×224 分辨率**。256×320 aspect 跟老 baseline 一致，若后续要复现 Stage1 pipeline 这条线生态最熟。
